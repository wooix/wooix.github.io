짐을 작은 가방에 넣으려면 물건을 압축해야 합니다. 하지만 가방이 작아졌다고 이동 시간이 같은 비율로 줄어들지는 않습니다. 자주 꺼내는 물건이 깊이 들어가 있으면 오히려 불편해질 수도 있습니다. 모델을 장치에 올릴 때도 <strong>Compression(압축)</strong>과 실제 실행 성능을 나누어 생각하면 이해하기 쉽습니다.

<strong>AWQ(Activation-aware Weight Quantization, 활성값 인지 가중치 양자화)</strong>는 가중치를 낮은 비트 수로 표현하면서 중요한 채널의 오차를 줄이는 방법입니다. 논문은 TinyChat이라는 실행 시스템도 함께 제시합니다. 압축 방식과 실행 방식이 함께 맞아야 메모리 절약이 실제 속도로 연결된다는 관점으로 읽을 수 있습니다. [AWQ 원문, §3–4](https://arxiv.org/html/2306.00978v5#S3)

> <strong>읽기 기준</strong> · 최초 공개는 <strong>2023년 6월 1일</strong>이며, 이 글은 2024년 7월 18일의 v5를 확인했습니다. SLM(Small Language Model, 소형 언어 모델)을 장치에서 실행하기 위한 기초 노트입니다. 원 논문의 LLM(대규모 언어 모델) 실험을 모든 SLM 장치의 성능 보장으로 해석하지 않습니다. [논문 이력](https://arxiv.org/abs/2306.00978)

## Quantization: 숫자를 적은 비트로 표현하기

<strong>Quantization(양자화)</strong>은 모델의 숫자 표현에 사용하는 비트 수를 줄이는 방법입니다. AWQ(활성값 인지 가중치 양자화)는 <strong>Weight-only Quantization(가중치 전용 양자화)</strong>를 다룹니다. 가중치가 4-bit라는 설명이 모든 활성값과 중간 계산까지 4-bit라는 뜻은 아닙니다. [AWQ 원문, §2–3](https://arxiv.org/html/2306.00978v5#S2)

예를 들어 가중치가 정확히 1B, 즉 10억 개라고 가정하면 다음과 같이 저장량을 계산할 수 있습니다. 아래는 비트 수만 계산한 예시이며 특정 제품이나 모델의 측정값이 아닙니다.

| 가중치 표현 | 단순 계산 | 가중치 데이터만의 저장량 |
| --- | --- | --- |
| 16-bit | 10억 × 16 ÷ 8 | 2 GB |
| 8-bit | 10억 × 8 ÷ 8 | 1 GB |
| 4-bit | 10억 × 4 ÷ 8 | 0.5 GB |

여기서는 1 GB를 10억 바이트로 셌습니다. <strong>Scale(스케일)</strong> 같은 양자화 메타데이터와 실행 중 사용하는 메모리는 계산에서 제외했습니다. 따라서 “4-bit 1B면 메모리 0.5 GB로 실행된다”는 결론을 이 표에서 얻을 수는 없습니다.

## Activation-aware: 무엇을 더 조심스럽게 압축할까

논문의 출발점은 일부 중요한 가중치를 보호하면 양자화 손실을 크게 줄일 수 있다는 관찰입니다. 중요도를 찾을 때 가중치 크기만 보지 않고 입력 <strong>Activation(활성값)</strong>의 분포를 참고합니다. 그러나 실제 AWQ를 “1%는 항상 FP16으로 남긴다”라고 설명하면 부정확합니다. 논문은 혼합 정밀도 구현의 부담을 피하려고 <strong>Channel Scaling(채널 스케일 조정)</strong>을 사용합니다. [AWQ 원문, §3.1–3.2](https://arxiv.org/html/2306.00978v5#S3.SS2)

채널의 가중치를 키우고 입력을 반대로 조정하면 양자화 전의 계산을 동등하게 유지할 수 있습니다. 그 상태에서 양자화하면 중요한 채널의 상대 오차를 줄일 수 있습니다. 조정값은 <strong>Calibration(보정)</strong> 과정의 활성값 통계로 찾으며, 모델을 역전파로 재학습하는 방식은 아닙니다. [AWQ 원문, §3.2](https://arxiv.org/html/2306.00978v5#S3.SS2)

가방의 모든 물건을 똑같이 누르기보다 깨지기 쉬운 물건의 포장을 조정하는 비유를 떠올려 봅시다. 자신의 데이터에 적용할 때는 “어떤 입력을 보고 깨지기 쉬운 부분이라고 판단했는가”가 다음 확인 항목입니다. 보정용 입력의 언어, 길이, 과제가 실제 사용과 어떤 관계인지 기록해 두면 좋습니다.

## Runtime: 파일이 작아진 다음에 볼 것

논문의 TinyChat은 Weight Packing(가중치 묶음 저장), Dequantization(역양자화), Kernel Fusion(커널 융합) 등을 사용합니다. 보고된 가속은 이러한 시스템과 비교 대상, 장치 조건이 결합된 결과입니다. Quantization(양자화) 비트 수만으로 동일한 가속을 예상할 수는 없습니다. [AWQ 원문, §4·§5.4](https://arxiv.org/html/2306.00978v5#S4)

SLM(소형 언어 모델)을 직접 실행할 계획이라면, 장치 이름 다음에 아래 표의 빈칸을 채우는 방식으로 준비해 볼 수 있습니다. 이는 이 글이 제안하는 측정 기록 양식입니다.

| 항목 | 기록할 내용 |
| --- | --- |
| Hardware(하드웨어) | 장치, 메모리 용량, 전력 설정 |
| Runtime(실행 환경) | 실행기 버전과 실제 사용한 연산 장치 |
| Model Format(모델 형식) | 양자화 방식, 비트 수, 모델 체크포인트 |
| Workload(작업 부하) | 입력 길이, 출력 길이, 동시 요청 수 |
| Quality(품질) | 원본과 양자화 모델의 동일 과제 평가 |

예를 들어 같은 모델 파일이라도 어느 연산이 가속기에서 실행되는지, 어느 부분에서 CPU를 사용하는지 확인하는 질문이 필요합니다. 특정 장치가 더 빠르다는 결론은 이 정보를 확보하고 측정한 뒤에 붙이는 편이 좋습니다.

## Measurement: 첫 토큰과 이후 토큰을 구별하기

장치에서 느끼는 사용감도 하나의 숫자만으로 표현하기 어렵습니다. 다음은 재현 실험을 위한 평가 제안입니다.

- <strong>Time to First Token(첫 토큰까지의 시간)</strong>: 모델을 불러오는 시간의 포함 여부를 밝히고, 입력을 보낸 뒤 첫 출력까지 측정합니다.
- <strong>Generation Throughput(생성 처리량)</strong>: 첫 토큰 이후에 얼마나 빠르게 출력하는지 측정하고 단위를 기록합니다.
- <strong>Peak Memory(최대 메모리)</strong>: 짧은 질문뿐 아니라 실제로 사용할 긴 문서에서도 측정합니다.
- <strong>Task Accuracy(과제 정확도)</strong>: 빠른 출력이 원문 조건과 숫자를 정확히 유지하는지 함께 봅니다.

각 실험은 입력과 생성 설정을 고정하고 반복해 봅시다. 전원 연결 상태나 발열 조건도 적어 두면 다음 측정과 비교하기 편합니다. 아직 이 블로그에서는 특정 SLM이나 장치의 측정 결과를 제시하지 않습니다.

## Research Questions: 압축과 행동 조절의 접점

이 글에서 확장해 볼 질문은 “양자화 후에도 원하는 행동이 유지되는가”입니다. Alignment(정렬)나 Steering(행동 조절)을 적용한 모델이라면 답변 정확도와 함께 제어 효과를 다시 측정하는 실험을 설계할 수 있습니다.

또한 자신의 과제가 한국어 논문 요약이라면 영어 일반 문장 중심의 보정 자료와 한국어 연구 문장 자료를 비교해 볼 수 있습니다. 어느 쪽이 낫다고 미리 가정하지 않고, 실제 과제의 출력과 메모리·시간을 나란히 기록하는 연구 질문입니다.

## Vocabulary: 하드웨어 논문에 자주 나오는 말

| 영어 용어 | 한글 보조 설명 |
| --- | --- |
| Quantization | 양자화, 숫자의 표현 정밀도를 줄이는 작업 |
| Calibration | 보정, 변환에 필요한 통계와 설정을 찾는 과정 |
| Weight-only | 가중치 전용, 저비트 변환의 대상 범위 |
| Memory Bandwidth | 메모리 대역폭, 단위 시간에 옮길 수 있는 데이터량 |
| Kernel | 커널, 특정 연산을 실행하는 낮은 수준의 구현 |
| On-device Inference | 장치 내 추론, 서버 전송 없이 장치에서 모델을 실행하는 것 |

AWQ(활성값 인지 가중치 양자화)를 읽고 남길 질문은 두 개입니다. <strong>어떤 정보 손실을 줄였는가</strong>, 그리고 <strong>그 형식을 내 장치가 어떻게 계산하는가</strong>. 압축과 실행을 연결하면 다음에 배워야 할 하드웨어 지식도 구체적으로 보이기 시작합니다.
