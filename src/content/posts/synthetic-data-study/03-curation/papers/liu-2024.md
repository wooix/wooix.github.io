## 초록

<strong>Instruction Tuning(지시 미세조정)</strong>에 사용할 데이터를 자동으로 고르는 문제를 다룬다. 논문의 질문은 데이터를 얼마나 많이 생성할 것인가보다, 같은 학습 예산에서 어떤 자료를 골라야 모델의 <strong>Alignment(정렬)</strong>가 잘 이루어지는가에 가깝다. 이를 <strong>Complexity(복잡성)</strong>, <strong>Quality(품질)</strong>, <strong>Diversity(다양성)</strong>라는 세 차원으로 나누어 조사한다.

DEITA는 세 차원의 측정을 결합해 자료를 고르는 방법과, 그 자료로 학습한 LLaMA·Mistral 계열 모델을 가리킨다. 일부 비교에서 6K 자료만 사용한 <strong>Supervised Fine-Tuning(지도 미세조정, SFT)</strong> 모델이 훨씬 큰 데이터셋으로 학습한 모델과 비슷하거나 높은 점수를 얻는다. 별도로 6K SFT 후 10K 선호 쌍을 이용한 <strong>Direct Preference Optimization(직접 선호 최적화, DPO)</strong> 결과도 보고한다. SFT 자료 선택의 효과와 추가 선호 학습의 효과를 구분해서 읽어야 한다.

## 1. 서론

사전학습 모델이 가진 능력을 사람이 원하는 응답 방식으로 이끄는 데 좋은 데이터가 중요하다는 관찰에서 출발한다. 기존 연구에서는 적은 수의 예제로도 강한 결과를 얻었지만, 자료를 사람이 고르거나 경험적인 생성·선별 규칙에 의존했다. 그래서 “좋은 데이터”를 재현 가능한 측정과 선택의 문제로 바꿀 필요가 있다는 것이 서론의 논지다.

저자들의 가설은 복잡하고, 응답 Quality가 높으며, 서로 다양한 예제가 유리하다는 것이다. 그러나 세 속성을 말로 정의하는 것과 유용한 측정값을 만드는 것은 다르다. §2는 각 측정값으로 자료를 고른 뒤 실제 모델을 학습해 검증하고, §3은 측정값들을 결합한다. 측정값의 타당성을 평가 모델의 라벨 일치율만으로 판단하지 않는다는 점이 중요하다.

복잡성을 높인 질문이나 개선한 응답을 생성하는 과정은 **전체 학습 자료를 새로 만드는 목적보다 점수 예측기를 학습할 감독 자료를 만드는 목적**에 사용된다. 작은 시작 자료에서 여러 수준의 변형을 만들고 ChatGPT에 함께 비교하게 한 뒤, 그 점수를 예측하는 별도 모델을 학습한다. 논문에서 ChatGPT는 **gpt-3.5-turbo-0613**을 뜻한다. 이 생성·라벨링 모델과 최종 평가에서 쓰는 GPT-4를 혼동하지 않는다.

왼쪽은 질문만 단계적으로 바꾸어 Complexity를 비교하고, 가운데는 같은 질문의 응답을 바꾸어 Quality를 비교한다. 각 경로는 ChatGPT의 순위·점수 라벨에서 별도 점수 예측기를 학습하는 단계로 이어진다. 오른쪽은 기존 후보 자료에 두 점수를 부여해 곱한 뒤 중복을 제어하며 고르는 단계다. I는 질문, R은 응답이며, 화살표는 작업 순서다. 그림에서 뒤 변형의 점수가 높게 그려졌다고 모든 생성 변형이 실제로 개선됐다는 보장은 아니다.


## 2. Alignment에 좋은 데이터는 무엇인가?

좋은 자료의 조건을 검증 가능한 선택 문제로 정의하고, 공통 실험 설정에서 세 속성을 나누어 살핀다. 이 절에서 얻은 결과가 §3의 결합 전략을 설계하는 근거다.

### 2.1. 데이터 선택 문제

후보 자료 집합 $X=\{x_1,\ldots,x_n\}$에서 각 $x_i$는 질문·응답 쌍이다. 선택 전략 $\pi$로 $m$개를 고른 부분집합을 $S_\pi^{(m)}$라고 두고, 그 자료로 Instruction Tuning한 뒤의 성능을 $Q$라고 정의한다.

$$
\pi^*=\operatorname*{arg\,max}_{\pi}Q\left(S_\pi^{(m)}\right)
$$

이 식은 데이터 점수 자체를 가장 크게 만드는 것이 최종 목적이 아니라, **고정된 예제 수에서 학습 후 성능을 가장 높이는 선택 전략**을 찾는다는 뜻이다. 점수가 높아 보이는 자료도 학생 모델에 도움이 되지 않으면 좋은 선택 기준이 아니다.

논문은 $m$을 데이터 예산이라 부르고 학습 연산량과 비례하는 것으로 취급한다. 다만 예제 수는 전체 토큰 수나 총연산비와 동일하지 않다. 특히 여러 차례 이어지는 대화의 길이와 학습 반복 횟수도 비용에 영향을 주므로, 뒤의 “적은 데이터” 결과는 우선 **선택된 학습 예제 수**에 관한 주장으로 읽는다.

### 2.2. 실험 설정

#### 학습과 평가

§2의 기본 학생 모델은 **LLaMA-1-13B**, 선택 예산은 **6K**다. 각 측정 방법으로 6K를 고른 뒤 같은 학습 설정을 적용한다. 결과는 다양한 분야의 여러 차례 대화로 구성된 MT-Bench에서 GPT-4가 모델 응답을 채점한 점수로 비교한다. 이는 사람의 의도와 맞는 대화 수행을 측정하려는 평가이며, 모든 사실성·안전성·분야 능력을 하나로 증명하는 수치는 아니다.

데이터에 점수를 부여하는 방식과 선택 알고리즘을 함께 복잡하게 바꾸지 않도록, 기본적으로 높은 점수의 예제를 고르는 단순한 규칙을 사용한다. 자세한 학습 설정과 Diversity 실험의 추가 통제는 부록 A에 있다.

### 2.3. Complexity 관점 — Evol Complexity

질문이 길거나 어렵다는 특징 가운데 무엇이 실제 학습 성능에 연결되는지 조사한다. 이 실험은 각 방법의 Complexity 점수가 높은 순서대로 6K를 선택하므로, 응답 Quality나 Diversity를 동시에 최적화한 최종 DEITA와 구분해야 한다.

#### 비교 방법

Random Selection, 질문 길이, 사전학습 모델이 응답에 부여하는 <strong>Perplexity(혼란도)</strong>, ChatGPT의 직접 점수, 질문을 의미 트리로 바꿨을 때의 노드 수, InsTag가 부여한 의미·의도 태그 수, 응답 손실에 기반한 IFD를 비교한다. 각 지표는 “복잡한 질문”을 다른 방식으로 근사한다.

Direct Scoring과 Instruction Node는 모든 후보를 ChatGPT에 보내야 하므로 비용 때문에 각 풀에서 **50K를 무작위 추출한 후보 집합**에만 적용한다. 이에 맞춰 Evol Complexity도 50K 조건을 별도로 보고한다. 전체 풀 결과와 50K 결과를 같은 후보 조건의 비교처럼 묶으면 안 된다.

#### Evol Complexity

Alpaca에서 무작위 선택한 **2K** 질문·응답 쌍을 시작 자료로 쓴다. 각 질문에 제약 추가, 심화, 구체화, 추론 단계 증가를 적용해 **5번 변형**하고, 원본을 포함한 **6개 질문**을 만든다. ChatGPT는 한 원본에서 나온 변형들을 **하나의 프롬프트 안에서 함께 순위화하고 채점**한다.

독립적으로 하나씩 점수를 매기면 여러 질문에 비슷한 높은 점수를 주기 쉬우므로, 서로 가까운 변형들을 함께 제시해 미세한 차이를 드러내려는 설계다. 이어서 질문만 입력받아 이 점수를 예측하도록 **LLaMA-1-7B**를 학습한다. 이 7B 점수 예측기와 선택된 자료로 학습하는 13B 학생 모델은 역할이 다르다.

여러 차례 이어지는 대화에서는 각 턴의 질문을 채점한 뒤 합산한다. 따라서 대화 전체 점수는 한 턴의 난도뿐 아니라 턴 수의 영향도 받을 수 있다. 점수는 보편적 난도의 물리 단위가 아니라 특정 생성·비교·학습 절차가 만든 측정값이다.

### 2.4. Quality 관점 — Evol Quality

이번에는 질문이 얼마나 복잡한지보다 그 질문에 대한 응답이 얼마나 유용한지 살핀다. 높은 Quality 점수 순으로 6K를 선택하고 학습 후 성능을 비교해, 데이터 풀 상태에 따라 Quality 선별의 중요성이 달라지는지 확인한다.

#### 비교 방법

무작위 선택, 응답 길이, ChatGPT가 응답의 정확성을 직접 채점하는 Direct Scoring을 비교한다. 긴 응답은 정보가 많을 가능성을 나타내는 간편한 기준이지만 사실성·관련성·제약 충족을 직접 보장하지 않는다. 직접 채점 방식은 Complexity 실험과 마찬가지로 50K 후보 조건에서 평가한다.

#### Evol Quality

동일한 2K 시작 자료에서 **질문은 고정하고 응답을 변형**한다. 도움 정도, 관련성, 깊이, 창의성, 세부 내용을 개선하도록 요청하며 5회 변형 후 원본 포함 6개 응답을 얻는다. 같은 질문에 대한 응답들을 한 번에 순위화·채점한 뒤 그 라벨을 학습한다.

Quality 점수 예측기는 **질문과 응답을 함께 입력받는 LLaMA-1-7B**다. 질문만 보는 Complexity 예측기와 입력이 다르다. 원본보다 뒤에 생성된 응답이 길거나 매끄럽다고 자동으로 더 정확해지는 것은 아니며, ChatGPT의 비교 판단을 감독 신호로 쓰는 방법이라는 한계가 남는다.

### 2.5. Diversity 관점 — 임베딩 기반 접근

개별 예제가 좋아도 유사한 자료만 많이 선택되면 학습 범위가 좁아질 수 있다. 이 절은 이미 선택한 집합과 새 후보의 관계를 고려해 중복을 줄이는 절차를 비교한다.

#### 설정

선택 집합 $S$를 유지하면서 후보 $x_i$가 Diversity를 추가한다고 판단할 때만 넣는다. 판단 함수 $\mathcal{F}(x_i,S)$가 참이면 지시함수 $\mathbf{1}[\mathcal{F}(x_i,S)]$가 1이고, 그렇지 않으면 0이다. 예산 $m$을 채우거나 후보를 모두 검사하면 멈춘다.

이 실험은 Complexity·Quality 효과가 섞이지 않도록 점수 수준이 비슷한 후보 부분집합을 먼저 구성한다. 부록 A의 추가 통제 때문에 이 절의 Random Selection 수치가 Table 2·3의 Random Selection과 다르다. 표 사이의 절대 점수 차이를 Diversity 필터 하나의 손익으로 읽으면 안 된다.

#### 비교 방법

InsTag Diversity는 새 후보가 이전 선택 집합에 없던 태그를 추가하는지를 검사한다. $T_S$가 기존 태그 집합, $T_{x_i}$가 후보의 태그라면 다음 조건을 사용한다.

$$
|T_S\cup T_{x_i}|>|T_S|
$$

이 조건은 적어도 하나의 새 태그를 가져오는 후보를 선택한다는 뜻이다. 의미·의도를 태그로 압축하기 때문에 태그 체계와 태깅 모델에 선택 결과가 의존한다.

#### Repr Filter

LLaMA-1-13B로 문장을 표현하고 후보와 이미 선택된 자료의 최근접 관계를 계산한다. 태그 하나의 추가 여부보다 연속적인 벡터 표현으로 중복을 판단하려는 방법이다. 기본 임계값은 $\tau=0.9$다.

**원문 표기에 주의해야 한다.** §2.5와 Algorithm 1은 $d$를 “cosine distance”라고 부르면서 **$d<\tau$이면 채택**한다고 적는다. 통상적인 거리라면 가까운 예제를 채택하는 방향이 되어 중복 제거라는 설명과 충돌한다. 반면 유사도를 뜻한다면 임계값 미만을 채택하는 규칙으로 읽을 수 있다. 이 해설은 원문 표현을 임의로 고쳐 확정하지 않는다. 아래 Algorithm 1 설명에서도 원문의 부등호를 그대로 밝히며, 이를 거리·유사도 정의가 확인된 실행용 명세로 취급하지 않는다.

후보를 높은 결합 점수 순서로 검사하고 선택 집합과 비교한다는 전체 구조는 §3.1에서 설명한다. 임계값과 표현 모델 변화의 결과는 부록 C.1에서 검토한다.

## 3. DEITA — 데이터 효율적인 Alignment용 Instruction Tuning

앞 절에서 따로 살핀 Complexity·Quality·Diversity를 결합한다. 세 지표의 값을 병렬로 보고하는 데서 그치지 않고 실제로 어떤 순서로 후보를 채택할지 정하는 절이다.

### 3.1. 방법

#### 점수를 먼저 고려하고 Diversity를 반영하는 데이터 선택

질문의 Complexity 점수 $c$와 응답의 Quality 점수 $q$를 곱한 Evol Score를 사용한다.

$$
s=c\cdot q
$$

두 속성이 모두 높은 후보를 우선하려는 단순한 결합이다. 그러나 점수 척도에 의존하는 휴리스틱이지 두 속성의 확률을 곱하는 식이나 최적성이 증명된 목적함수는 아니다.

여러 턴의 대화는 **각 턴의 $c_tq_t$를 먼저 계산한 뒤 합산**한다. Complexity의 합과 Quality의 합을 곱하는 방법과는 다르다. 이 점수로 후보 풀을 내림차순 정렬하고, 높은 점수의 후보부터 Repr Filter로 중복을 확인하며 예산까지 선택한다.

**Algorithm 1의 단계별 의미** ([원문](https://arxiv.org/html/2312.15685v2#alg1))

1. 후보 풀 $X$와 예산 $m$을 입력받고 선택 집합을 준비한다.
2. $s=cq$에 따라 높은 점수부터 후보를 정렬한다.
3. 정렬 순서대로 후보와 선택 집합 사이의 최근접 관계를 검사한다.
4. 원문 의사코드의 조건 $d(x,S)<\tau$를 만족하면 후보를 추가하고, 아니면 건너뛴다.
5. 선택 예제 수가 $m$이 되면 종료한다.

본문은 최고 점수의 예제를 먼저 $S$에 넣는다고 설명하지만 Algorithm 1은 빈 집합에서 시작하며 첫 최근접 계산의 처리를 따로 쓰지 않는다. 또한 거리 정의·부등호의 모호함은 §2.5와 같다. 따라서 위 단계는 **원문의 동작 설명**이며 빈 집합 처리까지 완성된 구현으로 제시하지 않는다.

점수만으로 상위 $m$개를 고르는 방식과 달리, 뒤에 오는 후보는 이미 선택한 예제에 따라 채택 여부가 달라진다. 다만 저자의 “세 속성을 보장한다”는 표현은 이 지표와 필터를 적용한다는 의미로 한정해야 한다. 실제 사실성, 과제별 충분한 표본 수, 공정성까지 보장하는 절차는 아니다.

#### DEITA 학습

선택한 $m$개 예제로 학습한 모델을 $\mathrm{DEITA}_m$이라고 부른다. LLaMA-1-13B·LLaMA-2-13B·Mistral-7B에 적용해 한 가지 학생 모델에만 의존하는 결과인지 살핀다. 이 모델들은 선택에 사용하는 7B 점수 예측기와 구분한다.

### 3.2. 실험 설정

§3의 선택 풀은 **$X_{sota}$**이고 예산은 6K·10K다. MT-Bench와 AlpacaEval, 당시 Open LLM Leaderboard의 ARC·HellaSwag·MMLU·TruthfulQA 네 과제를 사용한다. 먼저 LLaMA-1-13B에서 LIMA·Alpagasus·TAGLM 등과 선택 방법을 비교하고, 다음으로 세 학생 계열에서 공개 모델과 비교한다.

중심 비교는 SFT 자료 선택이므로 SFT만 수행한 결과다. 추가 참고점으로 가장 강한 SFT 모델에 DPO를 적용하며, 이때는 Zephyr에 쓰인 UltraFeedback 유래 비교 데이터에서 **10K 선호 쌍을 무작위 선택**한다. DPO 자료까지 DEITA로 선별했다는 뜻이 아니다.

AlpacaEval은 출력 간 선호 평가를 %로 보고하고 MT-Bench는 채점 점수를 보고한다. 이 논문의 AlpacaEval을 후속 연구의 AlpacaEval 2나 길이 보정 점수와 혼용하지 않는다. 선택 데이터 수·기반 모델·학습 방식·평가 종류를 함께 확인해야 한다.

저자는 MT-Bench와 AlpacaEval의 향상 폭이 다른 이유를 과제 구성에서 찾는다. Figure 3에서 DEITA-Mistral의 코딩·수학·추론 강점이 나타나며, 이런 능력이 AlpacaEval에서는 덜 부각된다고 해석한다. 이는 평가 구성에 대한 해석이지 두 평가의 차이를 완전히 분리해 증명한 인과 실험은 아니다.

#### 데이터 규모 증가

<figure class="paper-figure" id="figure-2"><a href="https://arxiv.org/html/2312.15685v2/scaling_curve1.svg" target="_blank" rel="noopener"><img src="https://arxiv.org/html/2312.15685v2/scaling_curve1.svg" width="468" height="360" alt="선택 예제 수에 따른 MT-Bench 성능 변화." loading="lazy" /></a><figcaption>Figure 2. 선택 예제 수에 따른 MT-Bench 성능 변화. <a href="https://arxiv.org/html/2312.15685v2#S3.F3.fig1">원문</a></figcaption></figure>

가로축은 1K·3K·6K·12K·24K·전체 약 300K의 데이터 예산이고 세로축은 MT-Bench 점수다. 노란 원은 무작위 선택, 초록 삼각형은 TAGLM, 붉은 별은 DEITA다. 적은 예산에서 DEITA가 강하고 6K 부근 이후 점수가 낮아지는 구간도 나타난다. 전체 데이터를 사용할 때 방법 간 차이는 사라진다. 가로축은 예제 수 범주이므로 점 사이의 간격을 실제 데이터량의 선형 비율로 해석하지 않는다.

저자는 약 300K 전체 학습과 비슷한 MT-Bench 성능을 3K로 얻었다는 점을 강조한다. 이는 해당 풀·학생·학습 설정·평가에서 **선택 예제 수 약 100배 감소**의 관찰이며 총학습비·점수 예측기 준비비까지 100배 감소했다는 측정은 아니다.

선택량이 늘면서 성능이 처음 좋아졌다가 낮아지는 구간은, 기존 풀에 자료가 많아도 추가 자료가 항상 학습에 도움이 되지는 않음을 보여 준다. 하지만 Figure 2의 6K 정점이 모든 모델이나 데이터 풀의 최적 예산이라는 의미는 아니다. 원문 이 문단은 규모 그래프를 Figure 3으로 지칭하지만 실제 규모 그래프는 **Figure 2**, Figure 3은 과제별 레이더 그림이다.

## 4. 결론

좋은 Instruction Tuning 자료를 Complexity·Quality·Diversity라는 관점으로 나누어 측정하고, 각 지표의 유용성을 실제 학습 결과로 확인했다. 변형 예제를 함께 비교해 만든 점수 예측기와 표현 기반 중복 제어를 결합하면, 실험한 여러 조건에서 적은 자료로 경쟁력 있는 모델을 학습할 수 있다는 것이 결론이다.

효율성 주장은 학습 예제 수와 비교 조건에 한정해서 읽는다. 점수 예측기의 감독은 ChatGPT 판단에 의존하고, 평가별 우열도 일치하지 않으며, 모든 자료 풀에서 같은 예산과 임계값이 최적임을 보인 것은 아니다. 이 논문이 제공하는 핵심은 고정된 선별 규칙의 만능성보다, 선택 기준을 학습 후 성능으로 검증하는 구성이다.

## 부록 A. 상세 설정

### Diversity 기반 데이터 선택

§2.5에서는 Complexity·Quality가 다른 자료를 비교해 생기는 혼동을 줄이려고, 두 점수의 곱이 비슷한 자료로 새로운 후보 풀을 먼저 만든다. 원문은 선택 자료와 전체 풀의 평균 점수 수준 차이를 최대 2 이내로 제한한다고 설명한다. 이후 같은 후보 조건에서 Diversity 선택 방법을 비교한다.

이 통제는 Diversity 실험을 최종 DEITA 파이프라인과 구별하게 한다. §2.5의 결과는 후보 풀을 제한한 상태의 비교이고, §3의 최종 방법은 전체 후보를 결합 점수 순으로 우선시하면서 Diversity를 적용한다.

### DEITA 학습

7B 모델은 A100 네 장, 13B 모델은 여덟 장으로 학습한다. DeepSpeed ZeRO Stage 3와 FlashAttention-2를 사용하며, 여러 턴 대화는 Vicuna 방식으로 구성하고 최대 입력 길이는 **2048**로 맞춘다. 기반 모델에 따라 배치·학습률·반복 횟수가 다르므로 단순한 예제 수 비교만으로 연산량을 확정할 수 없다.

## 부록 C. 분석

### C.1. Repr Filter 분석

$\tau$를 0.8·0.85·0.9로 바꾸고 표현 모델을 비교한다. <strong>Model-based(학습 대상 모델 기반)</strong>는 이후 학생으로 학습할 LLaMA-1-13B 표현이고, <strong>Semantic-based(문장 의미 표현 기반)</strong>는 E5-Large-V2다. 후자는 제한된 문맥 길이를 고려해 토큰 임베딩을 평균해 문장을 표현한다고 기술한다.

LLaMA-1 표현은 세 임계값 모두 무작위 기준보다 높고 임계값 변화에 상대적으로 안정적이다. E5 표현은 임계값에 더 민감하다. 저자는 의미 검색 벤치마크에서 강한 임베딩이 데이터 선택에서도 항상 최적인 것은 아니며, 학생 모델 표현이 이후 학습과 관련된 속성을 담을 가능성을 제안한다. 이는 결과를 설명하는 가설로, 어떤 속성이 인과적으로 작동했는지 분리한 실험은 아니다.

가로축은 τ, 세로축은 MT-Bench 점수다. 노란 원은 LLaMA-1-13B, 초록 삼각형은 E5-Large-V2, 점선은 무작위 선택이다. 두 방법 모두 이 그림에서는 τ가 커질 때 점수가 높아지지만 E5의 변화 폭이 더 크고 τ=0.8에서는 무작위 기준보다 낮다. LLaMA 표현의 상대적 안정성은 세 임계값 범위에서의 관찰이며 모든 τ 범위의 강건성을 의미하지 않는다.


## 부록 D. 사람 평가

### 설정

MT-Bench 문제의 난도가 사람 평가에 부담이 된다고 판단해, LIMA 테스트셋에서 **100개 질문**을 무작위로 골라 평가한다. MTurk에서 먼저 시도했지만 답변 판단의 일관성과 지시 준수 문제를 겪어, 최종적으로 **동료 연구자 네 명**을 평가자로 사용한다.

## 부록 E. 프롬프트 예시

측정값이 어떻게 만들어졌는지 확인할 수 있도록 비교 방식과 변형·채점 프롬프트를 제시한다. 아래 표는 반복되는 공통 문구를 줄인 한국어 요약·발췌이며, **실행용 원문 템플릿을 그대로 옮긴 것이 아니다**. 원문의 입력 자리표시자와 척도·제약은 관련 위치에서 밝힌다.

### E.1. Complexity 비교 방법


**Table 11. Complexity 직접 채점과 의미 트리 기준 — 한국어 요약·발췌.** ([원문](https://arxiv.org/html/2312.15685v2#A5.T11))

| 방식 | 입력·요구 내용 | 출력 |
| --- | --- | --- |
| Direct Scoring | 질문의 난도·Complexity 평가 | 1–10점 숫자만, 이유 없음 |
| Instruction Node | 질문을 의미 분석 트리로 재작성한 뒤 노드 수 계산 | 노드 수만, 이유 없음 |

질문 하나의 절대 점수를 요구하는 방식과 구조적 복잡성을 노드 수로 근사하는 방식이다. 이 프롬프트를 사용했다는 사실만으로 의미 트리가 안정적으로 만들어지거나 사람의 난도 판단과 일치함을 보장하지 않는다.


### E.2. Evol Complexity

#### Complexity를 높이는 프롬프트

공통 목표는 사람이 이해하고 답할 수 있는 범위에서 질문을 더 어렵게 바꾸는 것이다. 표·코드 같은 비텍스트 부분과 원래 입력을 삭제하지 않고, 질문을 지나치게 장황하게 만들지 않도록 **10–20단어만 추가**하라고 지시한다. 입력·출력 표식 자체가 재작성된 질문에 섞이지 않도록 금지한다.


**Table 12. 질문 변형: 제약 추가·심화 — 한국어 요약·발췌.** ([원문](https://arxiv.org/html/2312.15685v2#A5.T12))

| 변형 | 원문의 핵심 지시 |
| --- | --- |
| adding constraints | 기존 질문에 제약 또는 요구 사항 하나 추가 |
| deepening | 특정 사안에 관한 질문의 깊이와 폭 확대 |

두 방식은 동일한 재작성 틀에서 변형 방향만 바꾼다. 제약 추가는 과제의 요구 조건을 늘리고, 심화는 탐구 범위를 넓힌다. 요구 조건이 충돌하지 않는지까지 이 프롬프트만으로 검증한 것은 아니다.


**Table 13. 질문 변형: 구체화·추론 단계 증가 — 한국어 요약·발췌.** ([원문](https://arxiv.org/html/2312.15685v2#A5.T13))

| 변형 | 원문의 핵심 지시 |
| --- | --- |
| concretizing | 일반적인 개념을 더 구체적인 개념으로 대체 |
| increasing reasoning steps | 단순한 사고로 풀 수 있는 질문에 여러 단계의 추론을 명시적으로 요구 |

§2.3의 5회 변형을 만드는 재료다. 구체화나 추론 요청이 항상 실제 인지 난도를 높이는 것은 아니므로, 뒤의 묶음 비교로 점수를 다시 부여하는 단계가 필요하다.


#### 순위화와 채점 프롬프트

한 원본에서 나온 여러 질문을 함께 제시해 난도와 Complexity 순서로 비교한다. 기본 점수는 **1–5**, 평가 모델이 답하기 너무 복잡한 질문에는 **6**을 허용한다. 독립 직접 채점의 1–10점과 다른 척도다.


**Table 14. 질문 묶음 순위화·채점 — 한국어 요약·발췌.** ([원문](https://arxiv.org/html/2312.15685v2#A5.T14))

| 요소 | 원문의 내용 |
| --- | --- |
| 입력 | 여러 질문의 번호와 본문 |
| 기준 | 난도와 Complexity |
| 척도 | 기본 1–5, 너무 복잡해서 답할 수 없으면 6 |
| 출력 | 질문 번호별 Score 형식 |

§2.3은 원본 포함 6개 변형을 한 번에 제시한다고 설명하지만, 이 예시 템플릿에는 질문 자리표시자가 5개까지만 적혀 있다. 예시 템플릿과 본문 설명의 개수 불일치를 임의로 고쳐 숨기지 않는다.

**Table 15. 응답 Quality 직접 채점 — 한국어 요약·발췌.** ([원문](https://arxiv.org/html/2312.15685v2#A5.T15))

| 요소 | 원문의 내용 |
| --- | --- |
| 입력 | 질문과 응답 |
| 기준 | 질문·입력에 대한 응답의 정확성 |

이 기준은 정확성 중심이며, 다음 Evol Quality의 도움 정도·관련성·깊이·창의성·세부 내용까지 포함한 기준과 완전히 같지 않다. 따라서 두 방법의 차이를 묶음 비교 여부 하나만 바뀐 실험으로 해석하는 데에는 주의가 필요하다.


### E.4. Evol Quality

#### Quality를 높이는 프롬프트

질문을 고정하고 응답을 더 좋게 다시 쓰도록 요청한다. 원문의 표·코드·입력을 생략하지 않고 사람이 이해할 수 있어야 하며, 재작성 응답은 **10–20단어만 추가**하도록 제한한다. 아래 다섯 방향은 서로 다른 응답 속성을 강조한다.


**Table 16. 응답 변형: 도움·관련성·깊이 — 한국어 요약·발췌.** ([원문](https://arxiv.org/html/2312.15685v2#A5.T16))

| 변형 | 원문의 핵심 지시 |
| --- | --- |
| enhancing helpfulness | 사용자에게 더 도움이 되는 응답 |
| augmenting relevance | 주어진 질문과 더 관련 있는 응답 |
| enriching depth | 더 깊이 있는 응답 |

질문에 대한 사실성만이 아니라 유용성·관련성·깊이를 변화시키려는 지시다. 공개 예시에는 질문으로 “건강을 유지하는 팁 세 가지”가 고정되어 있고 응답 자리에 자리표시자가 있다. 이를 모든 실제 생성 질문이 같았다는 뜻으로 해석하지 않는다.


**Table 17. 응답 변형: 창의성·세부 내용 — 한국어 요약·발췌.** ([원문](https://arxiv.org/html/2312.15685v2#A5.T17))

| 변형 | 원문의 핵심 지시 |
| --- | --- |
| fostering creativity | 응답의 창의성 증가 |
| supplying additional details | 응답의 세부 내용 증가 |

창의성과 세부 정보는 과제에 따라 가치가 달라질 수 있다. 이 지시를 수행해 더 길어진 응답이 곧 사실적으로 더 정확하다는 보장은 없다. 이 두 템플릿도 원문 예시에는 같은 건강 관련 질문을 사용한다.


#### 순위화와 채점 프롬프트

여러 응답을 같은 질문 아래에 놓고 도움 정도, 관련성, 정확성, 깊이, 창의성, 세부 내용을 함께 고려한다. 각 응답에 **1–5점**, 이미 매우 잘 쓰여 더 개선할 수 없는 응답에는 **6점**을 부여한다. 높은 점수의 의미가 질문 Complexity의 “너무 어려워 답할 수 없음”과 다르다.


**Table 18. 응답 묶음 순위화·채점 — 한국어 요약·발췌.** ([원문](https://arxiv.org/html/2312.15685v2#A5.T18))

| 요소 | 원문의 내용 |
| --- | --- |
| 입력 | 질문 하나와 번호가 붙은 여러 응답 |
| 기준 | 도움 정도·관련성·정확성·깊이·창의성·세부 내용 |
| 척도 | 기본 1–5, 더 개선할 수 없을 만큼 잘 작성되었으면 6 |
| 출력 | 응답 번호별 Score 형식 |

이 라벨이 Quality 점수 예측기의 감독이 된다. §2.4는 원본 포함 6개 응답을 비교한다고 쓰지만, 예시에는 응답 자리표시자가 5개까지 있다. 또한 종합 Quality 판단을 요구할 뿐 외부 근거 대조나 실행 검증 절차를 포함하지 않으므로, 점수 예측기를 사실성 검증기로 간주해서는 안 된다.
