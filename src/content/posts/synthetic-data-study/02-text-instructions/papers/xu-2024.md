## 초록

**Alignment(정렬)**을 거친 **Large Language Model(대규모 언어 모델, LLM)**에 사람이 만든 질문을 주지 않고 **Instruction(지시문)**부터 생성하는 방법이 Magpie다. 이미 정렬된 모델이 대화 형식을 학습했다는 점을 이용해 사용자 발화가 시작되는 위치까지만 입력하고, 그 뒤에 올 질문을 모델이 이어 쓰게 한다. 생성한 질문에 다시 답하게 하면 학습용 질문·응답 쌍이 된다.

Llama-3 계열의 두 모델로 만든 대표 데이터는 총 4M 쌍이다. 그러나 주요 비교 실험은 그 전체가 아니라 300K 쌍으로 학생 모델을 **Supervised Fine-Tuning(지도 미세조정, SFT)**한 결과다. 이 구분이 초록의 효율성 주장을 읽는 출발점이다. 여기서 데이터 효율은 비교 실험의 학습 예제 수를 뜻하며, 생성기 사전학습·정렬에 이미 쓰인 자원까지 절감했다는 뜻은 아니다.

## 1. 서론

공개 가중치 모델을 사용할 수 있어도 그 모델을 정렬한 대화 데이터는 공개되지 않는 경우가 많다. 기존의 합성 방법도 사람이 쓴 시작 질문, 복잡한 생성 절차, 유료 모델 호출에 의존한다. 저자들은 공개된 정렬 모델 자체를 질문 생성기로 쓸 수 있는지 묻는다.

핵심 관찰은 대화 템플릿의 사용자 헤더 뒤에서 생성을 시작하면 모델이 질문을 써 준다는 것이다. 이는 기존 질문을 변형하거나 사람이 작성한 예시를 확장하는 방식과 구별된다. 다만 이미 정렬된 생성기의 능력을 활용하므로, 제목의 “from scratch”를 학습된 지식이나 정렬 데이터의 영향까지 없는 생성으로 이해해서는 안 된다.

아래 그림은 질문 생성, 응답 생성, 선택적 선별과 추가 학습으로 이어지는 전체 흐름이다. 이후 §2가 생성 방법을, §3이 데이터 특성을, §4가 학습 결과를 검증한다.

## 2. Magpie: 정렬 데이터 합성을 위한 확장 가능한 방법

### 대화 템플릿

**Chat Template(대화 템플릿)**은 사용자·모델·시스템 발화를 구분하는 특수 토큰의 배열이다. 원문은 일반적인 입력을 다음과 같이 쓴다.

$$x=T_{\mathrm{pre\text{-}query}}\oplus q\oplus T_{\mathrm{post\text{-}query}}$$

여기서 $q$는 질문, $\oplus$는 문자열 연결이다. **Pre-query Template(질문 앞 템플릿)**은 사용자 발화가 시작되는 자리까지 안내하고, 뒤 템플릿은 사용자 발화를 닫은 뒤 모델의 응답을 시작시킨다. Llama-3에서는 사용자 헤더가 `<|start_header_id|>user<|end_header_id|>`와 같은 형식이고, 응답을 만들 때는 질문 뒤에 `<|eot_id|><|start_header_id|>assistant<|end_header_id|>`가 이어진다.

따라서 **“empty input”은 사용자 질문 $q$를 비운다는 뜻**이다. 입력 토큰 전체를 없애는 방식이 아니다. 정렬되지 않은 아무 모델에 빈 문자열을 주는 실험도 아니다. 모델마다 학습에 사용한 Chat Template을 맞춰야 하는 이유가 여기에 있다.

### 2.1. Magpie 파이프라인

#### 개요

질문 생성과 응답 생성을 분리한다. 첫 단계에서 아직 존재하지 않는 질문을 얻고, 두 번째 단계에서 그 질문에 대한 학습 목표 응답을 얻는다. 같은 모델을 사용할 수 있지만 두 단계의 입력 형식과 생성 목적은 다르다.

#### 1단계: 질문 생성

정렬된 모델에 Pre-query Template만 제공해 사용자 질문을 자기회귀적으로 생성한다. 사용자가 써 둔 초기 질문이나 예시 목록은 필요하지 않다. 여러 번 샘플링하면 서로 다른 질문을 얻으며, 온도와 top-p 등 생성 설정이 품질·난도·다양성에 영향을 준다. 종료 토큰을 이용해 생성된 사용자 발화를 구분한다.

#### 2단계: 응답 생성

1단계에서 생성한 질문을 정상적인 대화 입력으로 감싸고 모델 응답을 생성한다. 그 결과가 SFT용 질문·응답 쌍이다. 이 단계에서 얻은 답이 사실적으로 정확하다고 자동 보장되지는 않으므로, §3의 응답 점수와 §4의 학습 평가가 별도로 필요하다.

#### 적용 가능성

본문의 대표 데이터는 **Magpie-Air 3M**과 **Magpie-Pro 1M**이다. 질문·응답 생성기는 각각 Llama-3-8B-Instruct와 Llama-3-70B-Instruct다. 둘 다 이미 정렬된 모델이며, §4의 주 학생 모델인 Llama-3-8B base와 역할이 다르다. Llama-3.1, Qwen2, Gemma-2, Phi-3 계열로의 확장과 전체 데이터군 통계는 부록 A에 제시한다.

#### 원리에 대한 저자의 해석

저자들은 질문 부분의 손실을 직접 최적화하지 않았더라도 정렬 모델이 질문 분포를 암묵적으로 배웠을 가능성을 제안한다. 이는 방법이 작동하는 이유에 대한 해석이다. 생성한 질문이 비공개 정렬 데이터의 정확한 복원본임을 입증한 결과로 읽어서는 안 된다.

### 2.2. Magpie 확장

#### 고품질 데이터 선별

입력·출력 길이, 과제 유형, 질문 품질·난도, 가장 가까운 질문까지의 거리, 응답 보상 점수 등을 사용해 데이터를 고른다. 생성과 선별을 분리하므로 원시 데이터 전체를 공개하면서 사용 목적에 따라 다른 부분집합을 만들 수 있다. 구체적인 여섯 가지 Pro 선별 구성은 부록 C에서 비교한다.

#### 여러 차례 이어지는 대화

**Multi-turn(다중 턴)** 확장은 앞선 질문과 응답을 보존하고 그 뒤에 다시 사용자 헤더를 붙인다. 모델이 후속 질문을 생성한 뒤 다시 답하게 하는 방식이다. 작은 모델이 사용자 역할을 유지하도록 시스템 메시지를 추가할 수 있다. 따라서 첫 질문 생성과 후속 질문 생성은 문맥 조건이 다르다.

#### 선호 데이터

**Direct Preference Optimization(직접 선호 최적화, DPO)**용으로 질문당 후보 응답 다섯 개를 온도 0.8에서 생성하고, ArmoRM-Llama3-8B가 평가한 순위로 선호·비선호 응답을 구성한다. Air-DPO와 Pro-DPO는 각각 100K 규모다. 이 선호는 사람의 직접 비교 라벨이 아니라 모델이 부여한 평가에 기반한다.

#### 분야별·다국어 데이터

시스템 메시지로 수학·코딩·번역·언어를 지정하거나 해당 분야에 특화된 정렬 모델을 사용할 수 있다. 기본 Magpie가 수작업 초기 질문 없이 작동한다는 주장과, 확장판에서 목적에 맞는 시스템 메시지를 작성한다는 사실은 함께 구분해야 한다.

## 3. 데이터셋 분석

### 3.1. 데이터셋 범위

질문을 all-mpnet-base-v2로 임베딩하고 **t-SNE(고차원 자료의 저차원 시각화)**로 투영해 다른 데이터셋과 비교한다. Magpie-Pro의 분포가 Alpaca·Evol Instruct·UltraChat의 여러 영역을 포괄한다는 것이 저자의 관찰이다. 실제 그림과 각 데이터셋 10K 표본 조건은 부록 D.1에 있다. 저차원 투영의 겹침은 주제 범위의 시각적 근거이지 모든 유용한 과제의 완전한 포괄성을 보장하지는 않는다.

### 3.2. 데이터셋 속성

#### 속성: 질문의 과제 유형

Llama-3-8B-Instruct가 질문에 주 유형과 보조 유형을 붙인다. 정보 탐색이 Pro의 절반 이상을 차지하고, 창작·조언·계획·수학 등 다른 유형도 포함된다. “다양하다”와 “균등하게 분포한다”는 다른 주장이다. 이 분류 결과는 부록 G의 고정된 라벨 체계와 평가 모델에 의존한다.

#### 질문의 품질과 난도

질문의 명료성·구체성·일관성을 품질로, 해결에 필요한 지식과 과제 수준을 난도로 평가한다. 각각 다섯 등급을 쓰며, 응답의 정답 여부를 여기에서 평가하는 것은 아니다. Air와 Pro 모두 평균 이상의 질문이 다수를 이루며, Pro의 평가가 더 낫다는 것이 본문의 해석이다.

#### 질문 사이의 유사도

**Minimum Neighbor Distance(최근접 이웃 거리)**는 각 질문 임베딩에서 가장 가까운 다른 질문까지의 거리다. FAISS로 이웃을 찾으며, 거리가 매우 작으면 중복되거나 매우 비슷한 질문일 가능성이 있다. 이 값은 임베딩 공간의 차이를 재므로 의미적 독창성이나 과제 가치 전체를 대신하지는 않는다.

#### 응답의 품질

**Reward Model(보상 모델, RM)**인 FsfairX-LLaMA3-RM-v0.1로 생성 응답을 평가하고, 같은 질문에 대한 base 모델 응답과 비교한다. base 응답은 URIAL 방식으로 유도한다.

$$\Delta r=r^{*}-r_{\mathrm{base}}$$

$r^{*}$는 정렬 모델의 응답 점수, $r_{\mathrm{base}}$는 비교용 base 응답 점수다. 차이가 양수이면 해당 RM이 정렬 모델 답변을 더 높게 평가한다. 질문마다 비교점을 두어 학습에 도움이 될 만한 차이를 찾으려는 설계이지만, 점수 차이를 정확성의 확률이나 학생 모델의 예상 성능 향상량으로 해석할 수는 없다.

위 패널은 가로축 최근접 거리와 세로축 대화 수의 분포다. 아래 패널은 정렬 모델 응답과 base 응답의 점수 분포 및 두 점수 차이의 분포를 겹친다. 차이가 주로 양수라는 관찰은 해당 RM과 base 비교 조건에서 더 나은 응답을 만들었다는 근거다. 질문의 난도 분포나 모든 답의 사실성을 직접 측정한 그림은 아니다.


### 3.3. 안전성 분석

Llama-Guard-2로 위험 가능성을 분류했을 때 Air·Pro 모두 위험 표시 비율이 1% 미만이었다. 이 절은 수작업 질문 없이 생성해도 위험 점검이 필요함을 보여 준다. 모델 분류기의 미탐지 가능성이 있으므로 “안전한 데이터임이 증명되었다”로 확장하지 않는다. 범주별 결과와 전문적 조언의 비중은 부록 D.2에서 다룬다.

### 3.4. 비용 분석

A100-SXM4-80GB 네 장, AMD EPYC 7763, 메모리 512GB 환경에서 vLLM과 bf16을 사용했다. Air 3M의 질문 생성은 1.55시간, 응답 생성은 50시간으로 총 약 206 GPU 시간이다. Pro 1M은 각각 3.5시간과 150시간으로 약 614 GPU 시간이다. 질문만 생성하는 시간과 응답까지 포함한 총비용을 혼동하면 안 된다.

논문의 서버 가격 가정에서 1K 쌍당 비용은 Air 약 0.12달러, Pro 약 1.1달러다. 이는 해당 실험과 당시 가격 가정의 추산이며 현재의 서비스 가격표가 아니다. 응답 생성이 총시간의 대부분이라는 점이 파이프라인 비용을 이해하는 핵심이다.

### 3.5. 추가 분석

부록 D는 길이·유형·어휘 분포뿐 아니라 생성 설정과 평가 모델 변경의 영향을 보완한다. 주 분석에서 관찰한 다양성이나 품질이 어떤 설정에 의존하는지 확인하기 위한 연결 절이다.

## 4. 성능 분석

### 4.1. 실험 설정

#### 비교 데이터와 학생 모델

ShareGPT·WildChat의 사람 대화 기반 데이터, Evol Instruct·UltraChat·GenQA의 합성 데이터, OpenHermes·Tulu의 혼합 데이터를 비교한다. 주 학생 모델은 **Llama-3-8B base**다. Magpie 질문·응답 생성에 사용한 Llama-3-8B-Instruct 또는 70B-Instruct와 학생의 출발점이 다르다. 같은 생성기를 사용한 Self-Instruct와의 비교는 별도로 부록 F.2에 있다.

#### 학습 설정과 데이터 규모

주 비교의 Magpie는 300K raw 또는 300K filtered다. raw는 원시 데이터의 앞쪽 표본이며 filtered는 품질 지표로 고른 부분집합이다. SFT 학습률은 $2\times10^{-5}$, 최대 길이는 8192이고, 선택적 DPO 단계의 학습률은 $5\times10^{-7}$다. 상세 설정은 부록 E에 있다. 원시 Air 3M와 Pro 1M를 합친 4M 학습 실험도 부록 F.3에 존재하지만, 주 결과의 300K 실험과 별도다.

#### 정렬 벤치마크와 평가 기준

AlpacaEval 2는 805개 질문, Arena-Hard는 500개 질의를 사용한다. 모델 출력끼리 비교해 평가 모델이 선호하는 비율인 **Win Rate(승률, WR)**와, 응답 길이에 따른 선호 편향을 조정하는 **Length-Controlled Win Rate(길이 보정 승률, LC)** 등을 보고한다. WR은 문제 정답률이 아니다.

AlpacaEval 표에는 GPT-4-Turbo(1106) 응답을 기준으로 삼은 결과와 공식 Llama-3-8B-Instruct 응답을 기준으로 삼은 결과가 따로 있다. Arena-Hard의 기준 응답은 GPT-4(0314)다. 따라서 서로 다른 열의 수치를 같은 기준의 점수로 비교해서는 안 된다. GPT 계열의 평가 판단, 기준 모델, 길이 조정 여부가 결과의 의미를 결정한다.

#### 추가 벤치마크

WildBench는 전체 평균에 가려질 수 있는 과제별 차이를 드러낸다. 별도로 MMLU·ARC·HellaSwag·TruthfulQA·WinoGrande·GSM8K·MMLU-Redux 등을 평가해 대화 선호와 지식·추론 능력을 구분한다. Pro-300K-Filtered에 수학·코딩·추론용 150K를 추가한 Pro-Mix는 총 450K다. GSM8K는 47.92에서 63.08로 높아지지만 공식 모델의 71.72에는 못 미친다. “좋은 대화 데이터”가 곧 충분한 추론 교육과정은 아니라는 근거다.

부록 F는 Multi-turn, 동일 생성기의 Self-Instruct, 학습량, 선별 구성, 응답 생성기 교체와 TrustLLM을 다룬다. 본문의 성능 차이를 질문 생성법 하나의 효과로 곧바로 환원하지 않도록, 영향을 줄 수 있는 요소를 나누어 보는 구성이다.

## 5. 관련 연구

### LLM 정렬

SFT와 선호 기반 최적화가 서로 다른 단계의 감독을 제공한다. 전자는 질문과 바람직한 응답을 학습하며 데이터 품질의 영향을 크게 받고, 후자는 응답 사이의 선호를 추가로 학습한다. Magpie도 질문·응답 쌍을 만드는 기본 절차와 선호 쌍을 만드는 확장을 구별한다. 이 소절은 §4에서 SFT와 SFT+DPO 결과를 따로 비교한 배경을 설명한다.

### 정렬 데이터셋 구축

저자는 사람이 LLM과 나눈 대화를 수집하는 방법과 LLM으로 질문을 합성하는 방법을 주요 두 범주로 구분한다. 전자는 질문 작성 비용과 유해 내용의 문제를, 후자는 초기 예시와 비슷한 질문으로 범위가 제한될 가능성을 갖는다. Magpie는 수작업 초기 질문에 대한 의존을 줄이는 합성 방법으로 자리 잡는다.

기존 NLP 자료를 질문·응답 형식으로 변환하는 방법과 여러 출처에서 자료를 선별·혼합하는 방법도 함께 살핀다. 변환 자료의 과제 범위가 제한될 수 있으므로 다양한 자료를 섞어 범위와 성능을 보완할 수 있다. 수학·추론용 자료를 Magpie와 결합할 가능성은 §4의 Pro-Mix 실험 및 다음 절의 한계 논의로 이어진다.

### 학습 데이터 추출

학습한 예제를 모델이 기억할 수 있다는 관찰은 비공개 자료 추출 연구와 연결된다. 기존 연구는 다양한 모델에서 사전학습·미세조정 자료를 추출하는 방법을 다루지만, 저자들은 Magpie의 목적을 적은 인력으로 공개 정렬 데이터를 생성하는 데 둔다. 이 목적의 차이가 생성 결과에 기억된 내용이 전혀 없다는 증거는 아니다. 대화 템플릿에서 질문을 생성할 수 있다는 관찰만으로 기억된 원문과 새 조합의 비율을 결정할 수는 없다.

## 6. 한계·논의·윤리적 고려

### 한계와 논의

원시 Magpie만으로 수학·추론 능력을 충분히 높이는 데에는 한계가 있다. 분야별 보강 데이터를 보태면 개선되지만 공식 모델과의 간격이 남는다. 이는 생성 질문의 자연스러움·다양성, 감독 응답의 품질, 특정 목표 능력을 훈련할 자료의 비중이 서로 다른 문제임을 보여 준다. 저자들은 추론 능력의 추가 개선을 후속 연구 방향으로 제시한다.

### 사회적 영향과 잠재적으로 유해한 결과

확장 가능한 데이터 합성으로 지시 수행과 정렬을 개선하려는 목적에도 불구하고, 생성된 질문·응답을 그대로 학습하면 위험한 행동으로 이어질 수 있다. 위험 가능성이 있는 자료가 실험상 1% 미만이었으며 저자는 선별로 이를 줄일 수 있다고 설명한다. 다만 완전히 제거됐다고 증명하지는 않는다. 정렬 모델을 생성기로 쓴다고 생성 데이터와 그 데이터로 학습한 모델의 안전성이 자동으로 이어지지 않는다는 점은 부록 F.6 결과와도 연결된다.

## 7. 결론

Magpie는 정렬된 공개 모델의 Chat Template을 이용해 수작업 초기 질문 없이 질문·응답 쌍을 만드는 간단한 방법을 제시한다. 대규모 원시 데이터 생성과 목적에 맞는 부분집합 선별을 연결하고 여러 학생 모델에서 실용성을 보였다. 결론의 성능 주장은 300K SFT, 추가 100K DPO, 벤치마크별 기준을 구분해서 읽어야 한다. 질문 생성의 자동화와 데이터 품질 보증은 별개의 검증 단계로 남는다.

## 부록 H. Magpie 예시

Llama-3-70B-Instruct가 생성한 대표 질문을 과제별로 제시한다. 정보 탐색은 커피의 깊이에 따른 색 차이, 추론은 스위치 세 개와 전구 세 개의 대응 찾기, 계획은 신규 금융 상담 고객을 만나기 전 준비, 편집은 문장의 인용부호와 표현 수정이다. 코딩은 주문 합계와 세금 계산, 수학은 날마다 일정 비율로 빠지는 물의 잔량, 역할극은 객관식 퀴즈 진행, 데이터 분석은 신입 직원 급여 평균과 국가 평균 비교를 다룬다. 창작·조언·발상·기타에는 가상 생명체 묘사, 스트레스 대처, 생일 행사 아이디어, 거꾸로 적힌 단어 풀이가 포함된다.

이 예시들은 생성 범위를 보여 주지만 답변이나 검증 결과를 제시하는 사례는 아니다. 따라서 여기에서 문제를 대신 풀거나 정답률을 추정하지 않는다. 익숙한 수수께끼가 나타나는 것 자체도 모든 질문이 새로운 문제라는 주장과는 구별해야 한다.

분야별 생성기 예시로 DeepSeek-Coder-V2는 이메일에서 도메인을 추출하는 Python 함수를 요청하고, Qwen2-Math-7B-Instruct는 직사각형을 두 배 확대했을 때 크기와 넓이를 묻는다. 이는 §2.2의 “특화된 정렬 모델을 생성기로 사용”하는 확장을 구체화한다.

다국어 예시에는 Qwen2-72B-Instruct가 만든 중국어·독일어·스페인어 등 질문이 있다. 원문의 **Portuguese로 붙인 예문은 이탈리아어이고, Italian으로 붙인 예문은 포르투갈어**로 되어 있어 라벨과 내용이 뒤바뀐 것으로 보인다. 원문 라벨을 언어 정확성의 검증 결과로 취급하지 않는다. 이 부록의 역할은 가능한 출력의 구체적 모습을 보여 주는 것이며, 언어별 규모·품질·학습 효과를 체계적으로 비교하는 실험은 아니다.
