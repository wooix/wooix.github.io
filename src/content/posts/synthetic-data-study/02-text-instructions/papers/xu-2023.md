최초 공개는 2023년 4월 24일, 학회 발표는 ICLR 2024다. 검토 판본은 2025년 5월 27일 공개된 **arXiv v3**이며, 게시일과 연구 시점을 구분한다. 아래는 v3 본문과 부록 A–L을 절 순서대로 해설한 것이다. 참고문헌 목록과 저자 정보는 제외한다. arXiv 서지 페이지의 초록과 v3 본문 초록의 표현이 달라, 이 글은 실제 v3 본문을 기준으로 한다.

## 초록

Large Language Model(대규모 언어 모델, LLM)의 Instruction Following(지시 이행)을 학습시키려면 다양한 요구와 답변이 필요하다. 사람이 복잡한 지시문을 대량으로 만드는 비용을 줄이기 위해, Evol-Instruct는 기존 지시문을 단계적으로 변형한다. 여러 단계에서 생성한 데이터를 섞어 LLaMA를 학습한 모델이 WizardLM이다.

v3의 핵심 주장은 이 데이터 구성 방법으로 Alpaca와 Vicuna 같은 비교 모델보다 여러 평가에서 더 높은 성능을 얻었다는 것이다. 방법의 이름은 Evol-Instruct, 학습된 모델의 이름은 WizardLM이며, 두 대상을 구분해야 생성 방법의 효과를 읽을 수 있다.

## 1 Introduction

기존 NLP 과제에 짧은 지시문을 붙이는 방식은 과제마다 표현과 요구가 제한되기 쉽다. 실제 사용자의 요구는 여러 조건과 과제를 결합하므로, 저자는 Open-domain Instruction(개방형 지시문)의 다양성과 복잡도를 함께 확보하려 한다. 사람에게 모든 작성을 맡기면 비용이 크고, ShareGPT에서 관찰한 난이도 분포에는 쉬운·중간 수준의 지시문이 많다는 것이 출발점이다.

Evol-Instruct는 In-depth Evolving(지시문을 더 복잡하게 만드는 변형)과 In-breadth Evolving(새로운 지시문으로 범위를 넓히는 변형)을 결합한다. 전자는 조건 추가, 질문 심화, 개념 구체화, 추론 단계 증가, 입력 복잡화의 다섯 방식이고, 후자는 기존 지시에서 영감을 얻어 새로운 요구를 만드는 방식이다.

그림의 출발점은 `1+1=?`다. 파란 화살표는 같은 출발점에 조건·구체적 상황·추론·코드나 표 입력을 덧붙이는 변화를, 빨간 화살표는 빛의 속도나 광합성 같은 다른 요구로 넓히는 변화를 표시한다. 그림은 변형 연산의 방향을 보여주는 예시이며, 각 생성 질문이나 답변의 정확도를 검증한 결과표는 아니다.

연구는 Alpaca의 52,000개 지시문에서 시작해 네 차례 변형으로 약 250,000개를 얻는다. 주 비교에서는 이 가운데 70,000개를 뽑아 LLaMA 13B를 학습한다. Vicuna와 학습 예제 수를 맞추고 Alpaca도 70,000개로 늘린 이유는, 단순히 예제 수가 늘어서 생긴 효과와 변형 방법의 효과를 구분하려는 것이다. 초기 Alpaca에는 사람이 쓴 175개 과제의 영향이 있으므로 완전히 인간의 기여가 없는 데이터는 아니다.

## 2 Related Work

### Closed domain instruction tuning

T5의 통일된 text-to-text 형식에서 FLAN·T0·ExT5, 더 많은 과제를 사용하는 ZeroPrompt·FLAN-T5로 이어지는 흐름을 정리한다. 여러 과제의 지시문을 함께 학습하면 새 과제로 일반화할 수 있다는 근거를 인정하면서, 단일 과제와 단순 입력 중심의 학습이 복합적인 사용자 요구를 충분히 덮지 못한다는 문제를 제기한다.

### Open domain instruction tuning

InstructGPT와 Vicuna는 사람이 만든 개방형 요구를 활용하고, Alpaca는 소수의 사람이 쓴 과제에서 모델이 지시문을 생성한다. Orca는 답변뿐 아니라 추론 과정의 신호도 배운다. 이 대비에서 Evol-Instruct의 기여는 AI가 데이터를 만들었다는 사실 자체보다, 기존 지시문의 난이도와 복잡도를 의도적으로 변화시키는 절차에 있다.

## 3 Approach

방법은 지시문을 바꾸는 Instruction Evolver(지시문 변형기), 실패를 판별하는 Instruction Eliminator(실패 제거기), 완성된 데이터로 모델을 학습하는 단계로 구성된다.

<figure class="paper-figure" id="figure-2"><a href="https://arxiv.org/html/2304.12244v3/main.png" target="_blank" rel="noopener"><img src="https://arxiv.org/html/2304.12244v3/main.png" width="428" height="239" alt="Figure 2: 변형·실패 제거·학습의 전체 흐름" loading="lazy" /></a><figcaption>Figure 2. 변형·실패 제거·학습의 전체 흐름. <a href="https://arxiv.org/html/2304.12244v3#S3.F2">원문</a></figcaption></figure>

파란 화살표는 심화, 빨간 화살표는 범위 확장, 노란 화살표는 실패 제거에 해당한다. 살아남은 여러 단계의 지시문을 Instruction Pool(지시문 저장소)에 모은 뒤 기반 모델을 학습한다. 이 반복은 데이터 생성 과정이며, 매번 지시문을 변형할 때 WizardLM의 가중치까지 다시 학습한다는 의미는 아니다.

### 3.1 Definition of Instruction Data Evolution

초기 데이터는 지시문 $I$와 응답 $R$의 쌍으로 정의한다.

$$
D^{(0)}=\{(I_k^{(0)},R_k^{(0)})\}_{k=1}^{N}
$$

한 차례 변형에서는 $I^{(t)}$를 $I^{(t+1)}$로 바꾸고, 바뀐 지시문에 맞는 $R^{(t+1)}$를 다시 생성한다. 이를 $M$회 반복하면 $D^{(1)},\ldots,D^{(M)}$을 얻는다. 원래 답을 그대로 붙이지 않는 이유는 요구가 달라지면 정답의 범위와 형식도 바뀌기 때문이다. 이 표기는 품질 점수가 아니라 데이터가 생성되는 관계를 나타낸다.

Open-domain Instruction에서는 입력과 지시문을 항상 별도 필드로 명확히 나눌 수 없다고 본다. 코드·표·문맥을 포함한 전체 요구가 변형의 대상이다.

### 3.2 Automatic Instruction Data Evolution

이 절은 지시문 변형, 응답 생성, 실패 제거의 순서를 구체화한다. 다양하고 어려운 데이터를 만드는 것과 사용할 수 있는 결과만 남기는 것을 같은 과정 안에서 다룬다.

#### Instruction Evolution

각 회차에는 직전 단계의 지시문을 꺼내 변형한다. 성공한 결과는 저장소에 추가하고, 실패한 경우 기존 지시문을 그대로 되돌려 다음 회차에 다시 변형할 기회를 준다. 실패한 새 문장을 그대로 학습에 넣는 구조가 아니다.

#### Instruction Evolver

In-depth Evolving은 지시문을 사람이 이해하고 답할 수 있는 범위에서 조금씩 어렵게 만든다. 다섯 연산 중 조건 추가는 요구사항을 하나 더 넣고, 심화는 질문의 깊이·범위를 늘리며, 구체화는 일반 개념을 더 특정한 개념으로 바꾼다. 나머지 두 연산은 여러 단계의 추론을 요구하거나 구조화된 입력을 포함하게 한다.

저자는 한꺼번에 지나치게 복잡한 자료로 채우는 일을 피하려고, 일반적인 심화 프롬프트에 추가 분량을 10–20단어로 제한한다. 기존 표·코드·입력은 보존하고, 변형을 지시한 메타 문구는 결과에 남기지 않게 한다. 다만 이 프롬프트 제약은 생성물이 항상 그 조건을 충족한다는 보장은 아니다.

입력 복잡화에는 In-context Demonstration(문맥 안의 예시)을 사용한다. XML·SQL·코드 등 실제 입력을 포함하는 예시로 형식 변화를 유도하며 자세한 내용은 부록 D에 있다. 다른 심화 연산의 프롬프트에는 이러한 예시가 필요하지 않다고 설명한다.

In-breadth Evolving은 기존 지시와 같은 분야에 속하지만 더 드문 새 지시문을 요구한다. 길이와 난이도는 기존과 비슷하게 유지하도록 한다. 따라서 범위를 넓히는 모든 변형이 동시에 난이도를 높이는 것은 아니다.

#### Response Generation

지시문 변형에 사용한 것과 같은 LLM으로 새 응답을 생성한다. 기본 실험에서는 바뀐 지시문 자체를 ChatGPT-3.5에 주고 반환된 본문을 응답으로 삼는다. 생성된 답을 별도의 외부 정답으로 교체하는 절차는 제시하지 않는다.

#### Elimination Evolving

다음 네 가지를 변형 실패로 본다.

- 이전 지시문과 비교해 정보 증가가 없다.
- 응답에 `sorry`가 들어 있고 80단어보다 짧다.
- 응답이 구두점과 불용어만으로 이루어져 있다.
- 생성 지시문에 `given prompt`, `rewritten prompt` 같은 변형 지시용 문구가 복사된다.

첫 조건은 모델 판단이고 나머지는 출력의 특징을 이용한다. 짧은 사과문을 실패로 보는 것은 응답하기 어려운 요청을 포착하려는 경험적 규칙이다. 이 검사를 통과했다고 답변의 사실성이나 추론 정확성이 모두 검증된 것은 아니다. 본문은 첫 조건의 자세한 설명을 부록 G로 연결하지만, 두 지시문의 동등성 판정 프롬프트는 실제로 **부록 F**에 있다.

### 3.3 Finetuning the LLM on the Evolved Instructions

초기 데이터와 모든 회차의 데이터를 합치고 섞은 뒤 학습한다. 가장 어려운 마지막 회차만 사용하는 것이 아니라 다양한 수준을 함께 제공하려는 선택이다. 주 비교에서는 합친 자료에서 기준 모델과 같은 수의 예제를 뽑는다. 이는 예제 수를 통제한 비교이며, 모든 데이터의 내용과 응답 길이까지 동일하게 맞췄다는 뜻은 아니다.

학습에는 Vicuna의 대화 형식을 사용한다. 사용자와 도움을 주는 Assistant(응답자)의 대화를 문자열로 구성하여, 사전학습 모델이 지시문에 맞는 응답을 내도록 학습한다.

## 4 Experiment

자동 평가와 사람 평가를 함께 사용해 일반 지식, 추론, 코드, 수학, 대화형 응답을 비교한다. 아래 성능은 해당 논문의 판본·모델·데이터 조건에서 얻은 결과다.

### 4.1 Baselines

ChatGPT-3.5, Alpaca, Vicuna와 LLaMA 13B 계열의 Baize·CAMEL·Tulu를 비교한다. Alpaca는 원래 공개된 모델을 그대로 쓰는 대신, Self-Instruct 방식으로 예제를 52,000개에서 70,000개로 늘리고 응답을 ChatGPT로 다시 생성한 뒤 LLaMA 13B를 학습한다. Vicuna는 ShareGPT의 70,000개 대화로 학습한 13B-v1.1이다. 따라서 이 논문의 Alpaca 결과를 원래 52,000개 버전의 결과로 인용하면 비교 조건이 달라진다.

### 4.2 Experiment detail

각 지시문마다 여섯 변형 프롬프트 중 하나를 같은 확률로 선택해 네 회차를 실행한다. 생성에는 temperature 1, top-p 0.9, frequency penalty 0, 최대 2,048 token을 사용한다. 원문은 전체 구성에 $52{,}000\times4\times3=624{,}000$회의 API 요청이 필요하다고 보고한다.

LLaMA 13B를 초기 모델로 사용하고 Adam, 초기 학습률 $2\times10^{-5}$, 최대 길이 2,048 token, GPU당 batch size 4로 세 epoch를 학습한다. 8대의 V100과 DeepSpeed ZeRO-3를 사용해 140시간이 걸렸다고 보고한다. 평가 시에는 WizardLM과 비교 모델에 Greedy Search(매 단계 가장 높은 확률의 token 선택)를 사용하고 최대 생성 길이를 2,048로 둔다.

### 4.3 Automatic Evaluation

#### OpenLLM Leaderboard of HuggingFace

MMLU는 다양한 학문 분야의 객관식 문제, ARC는 초등학교 수준 과학 문제, HellaSwag는 상식 추론, TruthfulQA는 잘못된 믿음을 재생산하는 경향을 평가한다. 한 평가만 높다고 모든 지시 이행 능력이 좋아졌다고 보지 않도록 범위를 나눈다.

#### Code Generation

HumanEval의 164개 함수 작성 문제로 코드 생성 능력을 평가하고 pass@1(한 번 생성한 답의 통과율)을 보고한다. 문장이 그럴듯한지보다 코드가 평가 조건을 충족하는지 보는 축이다.

#### Math Reasoning

GSM8k의 1,319개 초등 수학 시험 문제를 사용한다. 네 개의 예제를 제시하는 4-shot 조건에서 pass@1을 보고하므로, 예제를 제시하지 않는 평가와 직접 같은 조건으로 취급하지 않는다.

#### GPT-4 Evaluation

AlpacaEval·MT-Bench와 저자들이 만든 WizardEval에서 GPT-4의 판단을 이용한다. 이는 사람 평가와 별개의 평가 축이며, 모델이 답을 판단하는 방식 자체의 한계는 결론에서 인정한다.

### 4.4 Human evaluation

WizardEval은 실제 사용자 지시문 218개, 29개 skill·분야를 포함한다. GitHub·ShareGPT·Twitter·Reddit·Discord 등에서 수집한 요구를 바탕으로 만든 평가이며, 학습용 Evol-Instruct 데이터와 구분한다.

10명의 평가자에게 Alpaca·Vicuna·WizardLM·ChatGPT 응답을 무작위 순서로 보여 출처를 숨긴다. 관련성·지식 활용·추론·계산·정확성을 기준으로 평가하고, 비슷한 응답에는 같은 점수를 허용한다. 원문은 네 응답에 1–5의 순위를 부여하고 1을 가장 좋게 본다고 설명한다. 쌍별 승리·패배·동률 횟수를 집계하며 평가자 간 Kappa(우연 일치를 보정한 일치도)는 모두 0.6보다 크다고 보고한다.

## 5 Conclusions

저자는 지시문을 더 복잡하고 다양하게 바꾸는 자동 데이터 생성이 여러 공개 모델의 지시 이행을 개선한다고 결론짓는다. 실험은 코드·수학·GPT-4 평가와 사람 평가를 함께 다루며, 데이터의 양뿐 아니라 출발점과 변형 방식이 중요하다는 근거를 제시한다.

### Limitations

GPT-4 평가와 사람 평가 모두 확장성과 신뢰성에 한계가 있으며, WizardEval이 모든 사용 상황과 분야를 대표하지는 못한다고 명시한다. 따라서 특정 평가에서의 개선을 모든 실제 요청에서의 우위로 확대하지 않는다.

## Appendix A Deepening Prompt

질문에 특정 이슈에 대한 물음이 있으면 탐구의 깊이와 범위를 늘리라는 프롬프트다. 기존 입력·코드·표를 보존하고, 사람이 이해하고 답할 수 있게 하며, 추가 분량은 10–20단어로 제한한다. 이는 §3.2의 심화를 재현할 수 있도록 변형 지시를 구체화한 부록이다. 심화된 답을 제공하는 예시가 아니라 새 질문을 만드는 지시다.

## Appendix B Concretizing Prompt

일반적인 개념을 더 구체적인 개념으로 바꾸도록 한다. 나머지 보존·분량·출력 형식 제약은 A와 같은 골격이다. 깊이를 늘리는 A와 달리 개념의 구체성을 바꾸는 연산이므로, 두 연산을 같은 “문장을 길게 쓰기”로 묶으면 방법의 차이를 놓친다.

## Appendix C Increased Reasoning Steps Prompt

간단한 사고 몇 단계로 풀 수 있는 질문을 여러 단계의 추론을 명시적으로 요구하도록 바꾼다. 기존 입력을 보존하고 지나치게 장황하게 만들지 않는 제약은 유지된다. 추론 단계를 요구하도록 질문을 바꾸는 프롬프트이지, 실제 생성된 응답의 추론이 옳다고 판정하는 검증기는 아니다.

## Appendix D Complicate Input Prompt

입력 복잡화에는 데이터 형식별 예시를 제공한다. A–C의 짧은 변형 지시와 달리, 원래 질문과 구체적인 입력을 포함한 새 질문의 대응을 보여준다. 아래는 원문 Example D.1–D.6의 내용을 요약한 것이며, 실행해 검증한 프로그램은 아니다.

- D.1 XML: XML 통계 데이터를 HTML 표로 옮길 때 중복이 생기는 PHP 코드와 실제 데이터 구조를 포함한다.
- D.2 SQL: 메시지 테이블의 실제 행을 제시하고 그룹마다 마지막 레코드를 얻는 질의를 요구한다.
- D.3 Python: SQL 삽입문에서 정수·문자열 변수를 어떻게 다룰지 묻는 코드 입력을 포함한다.
- D.4 HTML: 스크롤바는 숨기되 스크롤 기능은 유지하려는 요청과 브라우저·CSS 조건을 제시한다.
- D.5 Shell: `scp` 포트 지정 시도와 오류 메시지를 포함하여 구체적인 명령 사용 문제로 바꾼다.
- D.6 JSON: 고객 구매 이력과 재구매 확률 질문에 구체적 JSON 입력을 포함하도록 요구한다. 이 예시의 출력 부분은 채워져 있지 않다.

마지막 예시는 완성된 JSON 데이터나 검증된 확률 계산을 제공하지 않으므로 내용을 추측해 보완하지 않는다. 이 부록의 목적은 입력 형식을 풍부하게 만드는 프롬프트를 보여주는 것이다.

## Appendix E Difficulty Judge Prompt

질문의 난이도와 복잡도를 1–10의 단일 점수로 평가하고 이유 없이 점수만 반환하게 한다. Figure 5와 평가 데이터의 난이도 분포 분석에 쓰는 도구다. 추상적인 난이도에 단일 수치를 부여하는 방식이며, 이를 객관적인 문제 난이도의 절대 척도로 정의하지는 않는다.

## Appendix F Equal Prompt

두 지시문이 같은 조건·요구사항을 가지며 질문의 깊이와 범위도 같은지를 판정한다. 출력은 `Equal` 또는 `Not Equal`이다. §3.2의 정보 증가 여부를 검사하는 프롬프트에 해당하며, 두 답변이 사실적으로 동등한지 검증하는 절차는 아니다.

## Appendix G Math Judgement Prompt

한 지시문이 수학 문제인지 묻고 `True` 또는 `False`만 받는다. ShareGPT seed의 GSM8k 성능을 분석할 때 수학 관련 자료 비중을 추정하기 위해 사용한다. 수학 문제의 정답을 채점하는 프롬프트는 아니다.

세 집단 모두 Alpaca보다 변형 데이터가 어렵고 C1에서 C4로 갈수록 더 어려워지는 경향을 보인다. 그러나 GPT-4의 절대 점수는 대체로 더 낮다. 원문의 “일치”는 동일한 점수를 준다는 의미보다 변화 추세가 비슷하다는 뜻이다.

추가로 여섯 데이터셋에서 300쌍을 구성해 어느 지시문이 더 어려운지 비교한다. 사람 간 Kappa는 0.68, ChatGPT와 사람 다수결 사이의 Kappa는 0.66이다. 이 결과는 선택한 표본의 비교 판단 일치에 대한 근거이며, 모든 유형의 난이도를 완벽히 측정한다는 뜻은 아니다.

## Appendix K Human Evaluation Aspects

§4.4의 평가 기준을 다섯 항목으로 정의한다. Relevance(관련성)는 문맥과 질문의 의미를 정확히 해석했는지, Knowledgeable(지식 활용)은 다양하고 자세한 지식을 문제 해결에 정확히 사용하는지다. Reasoning(추론)은 올바른 사고 과정이나 유효한 풀이 개념, Calculation(계산)은 수학·생물·화학·물리의 수식을 정확히 계산하는 능력, Accuracy(정확성)는 주어진 지시문을 올바르게 수행하는지를 본다.

이 기준은 사람이 응답을 비교할 때 무엇을 고려했는지를 밝힌다. 각 항목을 독립적인 자동 정답 검사로 구현했다는 뜻은 아니다.
