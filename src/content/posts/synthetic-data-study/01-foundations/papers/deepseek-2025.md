## 초록

저자는 Reinforcement Learning(강화학습, 이하 RL)으로 추론 능력을 유도하는 R1-Zero와, 읽기 쉬운 초기 데이터 및 다단계 학습을 추가한 R1을 구분한다. 생성된 추론 데이터를 작은 모델에 전달하는 Distillation(지식 증류)도 연구한다. 따라서 이 논문의 합성 데이터는 RL 중 발생하는 응답과, 선별 후 고정해 사용하는 학습 예제로 나누어 읽어야 한다.

## 1 서론

서론은 추론에 더 많은 계산을 투입하는 Test-time Scaling(평가 시 계산량 확장)의 문제를 제기한다. 저자는 긴 풀이를 사람이 모두 작성하는 방식의 대안으로 RL을 탐색하고, 그 결과를 읽기 좋은 모델과 작은 모델로 연결한다. 여기서 출발 모델은 이미 학습된 DeepSeek-V3-Base이므로, R1-Zero의 ‘지도 데이터 없는 RL’은 사전학습 자체가 없었다는 뜻이 아니다. [원문 §1](https://arxiv.org/html/2501.12948v1#S1)

### 1.1 기여

#### 사전학습 모델에 대한 대규모 사후학습

R1-Zero는 Supervised Fine-Tuning(지도 미세조정, 이하 SFT)을 선행하지 않고 RL을 적용한다. R1은 두 번의 SFT와 두 번의 RL을 조합한다. 전자는 추론 행동이 어떻게 유도되는지 탐색하고, 후자는 추론과 사용자 응답 품질을 함께 개선하려는 설계다.

#### 작은 모델에 대한 지식 전달

저자는 큰 모델에서 얻은 추론 패턴을 Qwen·Llama 계열에 전달한다. 기여는 작은 모델이 큰 모델과 완전히 같아졌다는 주장보다, 생성·선별한 응답으로 작은 모델의 추론 성능을 높이는 경로를 제시했다는 데 있다.

### 1.2 평가 결과 개요

수학·코딩·지식·일반 응답으로 평가 범위를 나누어 주요 결과를 예고한다. 본문은 R1의 여러 추론 평가 결과를 o1-1217과 비교하지만, 모든 능력과 사용 조건에서 동등하다고 결론내리지는 않는다. 자세한 생성 설정과 비교군은 §3에서 제시한다.

## 2 접근법

### 2.1 개요

방법은 R1-Zero, 초기 SFT를 둔 R1, 작은 모델로의 Distillation 순서다. 앞 단계에서 발견한 읽기 어려운 응답과 언어 혼합이 다음 단계의 데이터 설계를 요구한다. [원문 §2](https://arxiv.org/html/2501.12948v1#S2)

### 2.2 사전학습 모델에 직접 RL을 적용한 R1-Zero

이 절은 SFT를 선행하지 않아도 검증 가능한 보상으로 추론 성능을 높일 수 있는지를 시험한다. 무엇이 옳은 출력인지 알려 주는 보상은 여전히 존재한다.

#### 2.2.1 학습 알고리즘

##### 집단 상대 정책 최적화

Group Relative Policy Optimization(집단 상대 정책 최적화, 이하 GRPO)은 같은 문제에 여러 응답을 뽑고 집단 안의 보상을 비교한다. 별도의 Critic(가치 평가 모델) 대신 그 집단의 보상으로 기준을 잡는다.

핵심은 집단 안에서 보상을 정규화한 상대 우위다.

$$
A_i = \frac{r_i - \operatorname{mean}(r_1,\ldots,r_G)}{\operatorname{std}(r_1,\ldots,r_G)}
$$

$r_i$는 해당 응답의 보상이고 $G$는 같은 문제에서 생성한 응답 수다. 해당 보상에서 집단 평균을 빼고 집단 표준편차로 나눈다. 절대 점수만 보기보다 같은 문제에서 상대적으로 좋은 응답의 생성 가능성을 높이는 신호다. 목적함수의 Clipping(변화폭 제한)은 한 번에 정책이 지나치게 바뀌는 것을 억제하고, KL Penalty(기준 분포 이탈 벌점)는 참조 정책에서 크게 벗어나는 비용을 부과한다. 이 식은 데이터 품질 점수 자체가 아니라 정책 갱신 목적을 정의한다.

#### 2.2.2 보상 설계

정확도 보상과 출력 형식 보상을 사용한다. 수학의 결정 가능한 답은 규칙으로 확인하고 코드는 정해진 테스트 실행으로 피드백을 얻는다. 추론을 지정된 태그 안에 쓰도록 하는 형식 조건도 있다. 저자는 이 단계에서 신경망 기반 결과·과정 보상 모델을 사용하지 않으며, Reward Hacking(보상의 허점 악용)과 추가 학습 비용을 이유로 든다.

#### 2.2.3 학습 템플릿

템플릿은 추론 과정과 최종 답을 분리하도록 지시한다. 특정한 반성이나 탐색 전략을 강제하기보다 출력 구조만 제약하여, RL 과정에서 어떤 행동이 나타나는지 관찰하려는 목적이다.

#### 2.2.4 성능·자기 변화·재검토 행동

##### R1-Zero의 성능

원문은 AIME 2024에서 RL 학습이 진행되며 성능이 향상되는 모습을 보고한다. 한 응답의 평균 성공률과 여러 응답의 Majority Vote(다수결)는 다른 평가 조건이므로 혼동해서는 안 된다.

##### R1-Zero의 자기 변화 과정

학습이 진행되면서 평균 응답 길이가 늘어나고, 이전 단계를 다시 검토하거나 다른 해결 경로를 탐색하는 행동이 나타난다고 설명한다. 저자는 이 행동을 별도 전략으로 명시해 가르치기보다 RL의 상호작용에서 유도된 것으로 해석한다.

##### R1-Zero의 재검토 순간

저자는 초기 풀이를 되짚는 출력 사례를 ‘Aha Moment’로 설명한다. 원문은 사람이 말하는 듯한 문구를 포함한 재검토 행동을 보여준다. 이는 관찰한 생성 행동의 예시이며, 사람과 같은 자각을 측정한 결과는 아니다.

##### R1-Zero의 단점

읽기 어려운 응답과 언어 혼합이 남는다. 이 문제는 다음 절에서 읽기 좋은 초기 데이터를 사용해 R1을 만드는 동기로 연결된다.

### 2.3 초기 데이터를 사용하는 R1

이 절은 R1-Zero의 추론 성과를 유지하면서 가독성과 일반 응답 품질을 보완하는 방법을 제시한다.

#### 2.3.1 초기 학습

Cold Start(초기 학습)에 수천 개의 긴 Chain-of-Thought(단계적 추론, 이하 CoT) 예제를 사용한다. 생성 프롬프트, R1-Zero 출력, 사람의 후처리 등을 조합해 읽기 좋은 패턴을 만든다. 데이터의 역할은 새로운 RL 시작점을 마련하고 응답 형식을 정돈하는 것이다.

#### 2.3.2 추론 중심 RL

SFT 이후 수학·코드·과학·논리처럼 비교적 명확하게 판정 가능한 과제에서 RL을 수행한다. 언어 혼합을 줄이기 위해 CoT의 목표 언어 비율에 따른 보상도 추가한다. 저자는 이 제약이 가독성에 도움을 주지만 추론 성능에는 약간의 손실을 줄 수 있다고 보고한다.

#### 2.3.3 거절 샘플링과 SFT

추론 중심 RL이 수렴하면 그 체크포인트에서 후속 SFT용 데이터를 수집한다. 추론 외의 쓰기·역할 수행 등도 포함해 모델의 수행 범위를 넓힌다.

##### 추론 데이터

Rejection Sampling(기준을 통과한 응답만 남기는 표본 선별)으로 여러 응답 중 맞는 것을 수집한다. 이 단계에는 규칙 판정뿐 아니라 정답과 예측을 DeepSeek-V3에 주어 판정하는 경우도 포함된다. 따라서 모든 데이터가 동일한 실행 검증을 통과했다는 해석은 부정확하다. 언어 혼합이나 읽기 어려운 응답도 걸러 약 60만 개 추론 예제를 구성한다.

##### 비추론 데이터

쓰기·사실 질문·역할 수행·번역 등 약 20만 개의 비추론 예제를 구성하며 기존 DeepSeek-V3 SFT 자료의 재사용도 포함한다. 단순 인사에까지 CoT를 붙이지 않는 등 과제에 따라 출력 형식을 다르게 둔다. 추론 자료와 합친 약 80만 개로 DeepSeek-V3-Base를 두 차례 반복 학습한다. [원문 §2.3.3](https://arxiv.org/html/2501.12948v1#S2.SS3.SSS3)

#### 2.3.4 전체 시나리오에 대한 RL

두 번째 RL은 추론과 일반 사용자 선호를 함께 다룬다. 추론에는 규칙 기반 보상을, 일반 응답에는 선호를 반영하는 보상 모델을 사용한다. 유용성은 최종 요약을 중심으로, 유해성은 추론을 포함한 전체 응답으로 평가한다. 평가 대상 범위를 달리하는 것이 이 절의 중요한 설계다.

### 2.4 작은 모델로의 Distillation

선별한 약 80만 개 예제로 Qwen·Llama 계열을 직접 SFT한다. 논문에 제시된 증류 모델은 추가 RL 없이 학습한 결과다. 큰 모델의 확률 전체를 복제하는 방식보다 생성된 추론·응답을 학습 예제로 전달하는 방식에 해당한다.

## 3 실험

### 평가 과제

수학·코드·지식·지시 이행·일반 응답을 다양한 평가셋으로 측정한다. AlpacaEval 2.0과 Arena-Hard의 모델 판정에는 길이 편향을 줄이기 위해 최종 요약만 입력한다. Distillation 모델에는 수학·과학·코드의 대표 평가 결과를 보고한다.

### 평가 프롬프트

일부 지식·추론 과제에는 simple-evals 프롬프트를 사용하고, 일부 평가셋의 원래 Few-shot(소수 예제 제시) 프롬프트는 Zero-shot(예제 없이 지시)으로 변경한다. 저자는 Few-shot의 CoT가 R1 성능을 해칠 수 있다고 설명한다. 다른 과제는 원래 평가 절차를 따르며, 소프트웨어 수정 평가에서는 사용하는 실행 체계와 출력 형식도 지정한다.

### 기준선

DeepSeek-V3, Claude-Sonnet-3.5-1022, GPT-4o-0513, OpenAI-o1-mini, OpenAI-o1-1217과 비교한다. o1-1217은 API 접근 제약 때문에 공식 보고값을 사용한다. Distillation 모델에는 QwQ-32B-Preview도 비교군으로 포함한다.

### 평가 설정

최대 생성 길이는 32,768토큰이다. 긴 출력을 평가할 때 Greedy Decoding(가장 높은 확률의 토큰 선택)은 반복과 체크포인트 간 변동을 만들 수 있어 표본 생성으로 pass@1을 추정한다.

Temperature(생성 분포의 무작위성 조절값) 0.6, top-p 0.95로 문제마다 여러 응답을 생성한다. $\widehat{\mathrm{pass@1}}=\frac{1}{k}\sum_{i=1}^{k}\mathbf{1}[o_i\text{ is correct}]$는 단일 생성의 평균 성공 확률을 추정한다. $k$는 표본 응답 수이며, 지시 함수는 응답 $o_i$가 맞으면 1, 아니면 0이다. 여러 답 중 하나라도 맞으면 성공으로 세는 값과 다르다. AIME 2024에서는 64개 응답의 Majority Vote 결과도 별도로 보고한다. [원문 §3](https://arxiv.org/html/2501.12948v1#S3)

### 3.1 R1 평가

저자는 R1이 V3보다 여러 추론·지식 과제에서 나은 결과를 보였다고 보고한다. 다만 중국어 SimpleQA에서는 안전 학습 후 응답 거부가 늘어 성능이 낮아졌고, 실제 소프트웨어 공학 과제의 개선은 수학·알고리즘 문제만큼 크지 않다. 이 결과는 추론 성능 증가가 모든 과제의 균일한 증가가 아님을 보여준다.

### 3.2 증류 모델 평가

작은 모델을 동일한 추론 평가 묶음에서 비교한다. 저자는 SFT만으로도 강한 결과를 얻었다고 보고하되, 이 절의 결과와 추가 RL의 잠재 효과를 분리한다. 여기서 검증된 것은 선택한 기반 모델·데이터·평가의 조합이다.

## 4 논의

### 4.1 Distillation과 RL의 비교

Qwen-32B-Base에 직접 대규모 RL을 적용한 조건과 R1에서 증류한 조건을 비교한다. 보고된 평가에서는 증류한 모델이 더 우수하다. 저자는 작은 모델이 스스로 추론 패턴을 탐색하는 비용과, 큰 모델에서 얻은 패턴을 학습하는 효율을 대비한다. 모든 크기·예산에서 Distillation이 RL보다 우월하다는 보편 정리는 아니다.

### 4.2 성공하지 못한 시도

#### 과정 보상 모델

Process Reward Model(중간 풀이 단계 보상 모델, 이하 PRM)은 일반 추론에서 단계 경계를 정하기 어렵고, 중간 단계의 정답성을 판정하는 비용이 크다. 저자는 자신의 대규모 RL 설정에서 PRM의 추가 이점이 비용을 상쇄하지 못했다고 설명한다. 응답 재정렬이나 탐색 지원 가능성까지 부정하지는 않는다.

#### 몬테카를로 트리 탐색

Monte Carlo Tree Search(몬테카를로 트리 탐색, 이하 MCTS)는 응답을 부분으로 나눠 탐색하지만, 언어의 방대한 분기와 가치 모델 학습이 병목이 된다. 저자는 사전학습된 가치 모델을 활용한 추론 개선과, 탐색을 반복해 모델 자체를 지속 개선하는 문제를 구분한다.

## 5 결론·한계·향후 연구

결론은 직접 RL, 초기 데이터가 있는 RL, 작은 모델로의 Distillation을 하나의 개발 경로로 묶는다. 남은 한계로 함수 호출·다중 턴·복잡한 역할 수행·JSON 출력, 영어·중국어 외 언어 혼합, 프롬프트 민감성, 소프트웨어 공학 평가 비용을 명시한다. 이는 앞의 성과가 모든 사용 시나리오를 해결했다는 해석을 제한한다. [원문 §5](https://arxiv.org/html/2501.12948v1#S5)
