[합성데이터스터디 1강으로 돌아가기](/notes/synthetic-data-study/01-foundations/)

검토 원문: ACL Findings 2024 출판본, pp. 11065–11082. 초록, 본문 §1–5, 한계·윤리 진술, 부록 A–D를 읽었으며 참고문헌 목록과 감사의 글은 해설에서 제외했습니다.

## 초록

<strong>Large Language Model(대규모 언어 모델, LLM)</strong>을 이용한 <strong>Synthetic Data(합성 데이터)</strong>는 실제 데이터의 부족과 수집 비용을 줄이는 수단이지만, 생성 결과를 바로 학습에 넣을 수 있다는 뜻은 아니다. 저자들은 흩어진 연구를 생성, <strong>Data Curation(데이터 큐레이션)</strong>, 평가라는 공통 흐름으로 재구성한다. 새로운 생성 알고리즘의 성능을 입증하는 실험 논문이 아니라, 이미 발표된 방법들이 전체 과정의 어느 문제를 해결하는지 보여주는 서베이다. [원문 초록](https://aclanthology.org/2024.findings-acl.658.pdf#page=1)

## 1. 서론

모델이 강해져도 좋은 학습 데이터가 필요하다는 데서 논의를 시작한다. 저자들이 말하는 좋은 데이터는 단순히 문장이 자연스러운 데이터가 아니라, 사람의 의도와 맞는 풍부한 지도 신호를 담고 다양한 상황을 포괄하는 데이터다. 사람이 만든 데이터도 비용, 희소성, 개인정보 문제뿐 아니라 오류와 편향을 갖기 때문에, 인간 작성 여부만으로 품질을 판단할 수 없다.

LLM에는 데이터 생성기로서 두 장점이 있다. 사전학습으로 얻은 지식과 언어 능력이 내용을 만들고, 지시를 따르는 능력이 생성할 데이터의 속성을 조절하게 한다. 따라서 데이터 수집을 자동화하는 것에 더해, 모델이 무엇을 배울지 의도적으로 설계할 가능성이 생긴다. 작은 모델을 학습시키거나 특정 과제에 맞게 큰 모델을 조정하는 경우와, 다음 세대 모델의 학습 자료를 만드는 경우가 Figure 1에 함께 놓인다.

하지만 이 가능성은 정확성과 다양성이 동시에 확보된다는 보장이 아니다. 서론의 역할은 응용별 연구를 나열하는 데서 벗어나, 공통 단계별로 문제를 분석해야 하는 이유를 만드는 것이다. 이후 Figure 2가 이 분석의 지도가 된다. [원문 §1](https://aclanthology.org/2024.findings-acl.658.pdf#page=1)

## 2. 기초 개념

### 2.1. 문제 정의

식 (1)은 `D_gen ← M_p(T, D_sup)`으로 표현된다. `M`은 생성에 사용하는 사전학습 LLM, `p`는 프롬프트, `T`는 생성 과제, `D_sup`는 소수의 시드나 라벨 없는 입력 등 보조 자료다. `D_gen`은 최종 생성 데이터셋이다. 이 식은 품질 점수나 학습 손실이 아니라, 생성 결과가 무엇에 의해 결정되는지 정리한 인터페이스다.

여기서 중요한 것은 `D_sup`가 선택 사항이라는 점이다. 아무 자료 없이 생성하는 경우도 포함하지만, 기존 입력을 변형하거나 기존 샘플에 라벨을 붙이는 경우도 같은 틀로 다룬다. <strong>Data Annotation(데이터 주석)</strong>은 입력이 이미 주어진 특수한 생성 문제로 포함된다. 따라서 이 서베이의 범위는 새 문장 생성에만 한정되지 않으며, 선호 라벨이나 평가 결과를 생성하는 방식까지 이어진다. 세부 Annotation 방법은 부록 A로 넘긴다. [원문 §2.1](https://aclanthology.org/2024.findings-acl.658.pdf#page=2)

### 2.2. 생성 데이터에 요구되는 조건

저자들은 과제마다 좋은 데이터의 기준이 다르다는 전제 아래 두 공통 요구를 제시한다.

- <strong>Faithfulness(충실성)</strong>: 논리·문법의 일관성뿐 아니라 사실, 라벨, 과제 관련성이 올바른가. 긴 내용이나 전문 분야에서는 지식의 빈틈과 잘못된 생성이 더 문제가 된다.
- <strong>Diversity(다양성)</strong>: 길이, 주제, 표현 방식 등이 충분히 달라 실제 데이터의 여러 경우를 포괄하는가. 같은 패턴이 반복되면 학습과 평가가 좁은 범위에 갇힐 수 있다.

이 두 축이 이후 절을 연결한다. 생성 단계에서는 조건과 예제로 두 속성을 유도하고, Curation에서는 부족한 부분을 보정하며, 평가에서는 실제 달성 여부를 측정한다. 둘을 하나의 수치로 통합하는 최적화 공식을 제시한 것은 아니다. [원문 §2.2](https://aclanthology.org/2024.findings-acl.658.pdf#page=2)

## 3. 일반적인 작업 흐름

이 절은 연구를 생성·Curation·평가로 나눈다. Figure 2의 분류는 모든 방법이 각 단계를 똑같이 구현해야 한다는 규격이 아니라, 서로 다른 논문의 기여를 비교할 좌표계다. 생성에 성공해도 선별과 평가가 남으며, 평가 결과는 다음 생성 조건을 바꿀 수도 있다.

### 3.1. 데이터 생성

LLM의 내부 파라미터를 바꾸기보다 프롬프트와 실행 순서를 설계하는 방법에 초점을 맞춘다. 주요 갈래는 <strong>Prompt Engineering(프롬프트 설계)</strong>과 <strong>Multi-Step Generation(다단계 생성)</strong>이다. 전자는 한 번의 생성에 어떤 정보를 줄지를, 후자는 복잡한 목표를 어떤 순서로 나눌지를 다룬다. [원문 §3.1](https://aclanthology.org/2024.findings-acl.658.pdf#page=3)

#### 3.1.1. 프롬프트 설계

식 (2)는 프롬프트를 과제 설명, 생성 조건, 예시라는 세 요소를 템플릿으로 묶은 것으로 표현한다. 각각은 다음 역할을 가진다.

**과제 설명.** 사람이 주석 작업을 할 때 지침서를 받듯, LLM에도 과제 목적, 출력 형식, 라벨의 의미, 역할, 전문 지식을 알려준다. 단순한 역할 지정부터 외부 지식 그래프를 활용한 도메인 정보까지 포함한다. 핵심은 모델이 어떤 문장을 그럴듯하게 이어 쓸지가 아니라, 어떤 작업을 수행해야 하는지 명확하게 만드는 것이다.

**조건부 생성.** 같은 요청을 반복하는 것만으로는 높은 생성 온도를 사용해도 반복이 남을 수 있다. 식 (3)의 `조건 = {(속성, 값), …}`은 원하는 데이터를 명시적으로 지정하는 방법이다. 저자는 이 설계를 다시 두 문제로 나눈다.

- **조건의 범위:** 분류 라벨만 지정하면 클래스 비율을 조절할 수 있지만, 열린 응답의 다양한 속성을 다루기 어렵다. 주제·길이·문체 등으로 축을 늘리거나, 이야기에서 사용할 단어를 지정하는 방식이 소개된다.
- **조건의 값:** 어떤 축을 정한 뒤에는 그 축에 넣을 값을 확보해야 한다. 알려진 라벨에서 뽑거나, 외부 지식 그래프에서 가져오거나, LLM이 하위 주제를 생성하도록 할 수 있다. 개념 트리와 템플릿 변형도 이 단계의 선택이다.

**문맥 내 예제.** <strong>In-Context Learning(문맥 내 학습, ICL)</strong>은 원하는 패턴을 예제로 보여준다. 실제 라벨이 있으면 그것을 활용하고, 없는 상황에서는 생성한 예제를 다시 활용하는 방법도 있다. 하지만 문맥 길이가 제한되므로 예제를 아무렇게나 넣는 문제가 아니다. 유사도, 대표성, 정보량을 기준으로 선택하거나 예제에 설명을 추가하는 접근이 함께 소개된다. 예제를 주는 행위와 좋은 예제를 선택하는 행위는 구별해야 한다. [원문 §3.1.1](https://aclanthology.org/2024.findings-acl.658.pdf#page=3)

#### 3.1.2. 다단계 생성

식 (4)은 `D_i ← M_i,p_i(T_i, D_0:i−1)`이다. i번째 단계는 이전 단계의 결과를 입력으로 사용해 부분 과제를 수행한다. 이는 한 번에 모든 결과를 요구하는 대신 사람이 알고 있는 작업 순서를 생성 과정에 넣는다는 의미다. 단계마다 같은 모델을 써야 한다는 제한도 없다.

**샘플 단위 분해**는 하나의 샘플을 완성하기 위한 분해다. 대화에서는 발화를 번갈아 만들고, 질의응답에서는 문서·질문·정답·설명을 연결한다. 식 (5)의 `(D_1, …, D_k)`는 서로 다른 조각이 합쳐 하나의 데이터를 구성한다는 뜻이다. 다만 중간 산출물이 모두 최종 데이터에 남아야 하는 것은 아니며, 생성만 돕고 제외할 수도 있다. <strong>Chain-of-Thought(사고 연쇄, CoT)</strong>처럼 중간 추론을 생성하는 방법도 이 맥락에서 다루지만, 저자는 잠재적인 중간 정보의 체계적 활용이 아직 부족하다고 본다.

**데이터셋 단위 분해**는 전체 수집 방향을 조정한다. 이전 자료로 학습한 모델이 자주 틀리는 범주를 더 생성하거나, 먼저 만든 과제에서 새 과제를 확장하거나, 도메인 트리를 탐색한다. 식 (6)의 `D_gen = D_1 ∪ … ∪ D_k`는 매 단계에 만든 샘플 묶음이 최종 데이터셋으로 누적된다는 뜻이다. 앞 방식이 한 샘플의 완결성을 다룬다면, 이 방식은 전체 범위와 구성을 다룬다. [원문 §3.1.2](https://aclanthology.org/2024.findings-acl.658.pdf#page=5)

### 3.2. 데이터 큐레이션

많이 생성할 수 있다는 사실은 유용한 자료가 많이 생긴다는 사실과 다르다. 잘못된 라벨과 불필요한 샘플이 섞일 수 있어, 저자는 좋은 샘플을 남기는 방법과 기존 라벨을 고치는 방법을 구분한다. 이 구분은 버릴 것인지, 학습 비중을 줄일 것인지, 고쳐 쓸 것인지의 차이다. [원문 §3.2](https://aclanthology.org/2024.findings-acl.658.pdf#page=6)

#### 3.2.1. 고품질 샘플 필터링

<strong>Sample Filtering(샘플 필터링)</strong>은 `D_curated ⊂ D_gen`인 부분집합을 만드는 작업이다. 신뢰도, 학습 과정에서의 행동, 특정 라벨과의 생성 확률, 모델·실행·인접 샘플 사이의 일관성 등이 판단 신호로 쓰인다. LLM이 직접 품질을 채점하는 접근도 있다. Alpagasus는 이 서베이에서 자료의 개수보다 선별이 중요할 수 있음을 보여주는 사례로 배치된다.

<strong>Sample Re-Weighting(샘플 재가중)</strong>은 이분법적으로 버리는 대신 각 샘플의 학습 비중을 바꾼다. SunGen은 자동 가중치 조절, FewGen은 라벨 사이의 차이를 더 잘 구분하도록 하는 목적을 대표한다. 이 절의 공통점은 품질을 직접 아는 것이 아니라 대리 신호로 추정한다는 것이다. 신뢰도나 일관성은 해당 방법의 선택 기준이며, 정답성 그 자체로 정의되지 않는다. [원문 §3.2.1](https://aclanthology.org/2024.findings-acl.658.pdf#page=6)

#### 3.2.2. 라벨 개선

<strong>Label Enhancement(라벨 개선)</strong>은 입력을 유지하면서 잘못 붙은 감독 신호를 고친다. 생성 모델이 자신의 오류를 안정적으로 알아낼 수 있다고 가정하기 어려워, 사람이나 보조 모델을 활용한다.

사람이 개입하는 경우에는 불확실한 샘플을 우선 재검토하거나 동일 지침으로 사람과 LLM의 라벨을 비교한다. 정확성을 높일 수 있지만 비용이 생긴다. 보조 학생 모델을 사용하는 경우에는 <strong>Knowledge Distillation(지식 증류)</strong>을 통해 약한 라벨에서 과제에 유용한 정보를 학습하고, 그 결과를 다시 라벨 수정에 활용한다. FreeAL은 큰 모델과 작은 모델의 협업을, MCKD는 데이터 분할과 교차 라벨링을 통해 잘못된 라벨에 과적합하지 않도록 하는 설계를 보여준다.

학생이 교사보다 무조건 좋은 라벨을 만든다는 주장이 아니라, 약한 감독 신호에서 유용한 규칙을 학습할 수 있다는 가정에 기반한 방법들이다. 이후 §4.3은 이 협업을 더 넓은 연구 방향으로 확장한다. [원문 §3.2.2](https://aclanthology.org/2024.findings-acl.658.pdf#page=7)

### 3.3. 데이터 평가

<strong>Direct Evaluation(직접 평가)</strong>은 생성 데이터 자체를, <strong>Indirect Evaluation(간접 평가)</strong>은 그 데이터로 학습한 모델의 성능을 살핀다. 둘은 대체 관계가 아니다. 내용이 좋은지와 실제 학습에 도움이 되는지가 다른 질문이기 때문이다. [원문 §3.3](https://aclanthology.org/2024.findings-acl.658.pdf#page=7)

#### 3.3.1. 직접 평가

Faithfulness는 정답이 존재하면 정답과 비교하고, 열린 내용이면 사람이나 신뢰할 수 있는 보조 모델이 검토한다. 사람 평가의 샘플 수를 늘리면 더 많은 비용이 필요하며, 모델 평가에는 처리 길이와 전문 지식의 제약이 있다. 긴 내용에서 필요한 사실만 추출해 판단을 돕는 방식도 소개된다.

Diversity는 어휘 크기나 <strong>N-gram(연속된 N개 단위)</strong> 빈도로 측정할 수 있지만, 표면적으로 다른 문장이 같은 뜻일 수 있다. 이를 보완하기 위해 표현 벡터의 <strong>Cosine Similarity(코사인 유사도)</strong>나 샘플 사이 거리를 사용한다. 이런 측정값은 사후 보고뿐 아니라 기존 샘플과 다른 예제를 선택해 다음 생성을 유도하는 데에도 활용된다. [원문 §3.3.1](https://aclanthology.org/2024.findings-acl.658.pdf#page=8)

#### 3.3.2. 간접 평가

생성 데이터로 학습한 모델을 <strong>Benchmark(벤치마크)</strong>에서 평가하면 실제 과제에 대한 기여를 볼 수 있다. 예를 들어 TruthfulQA는 참인 주장을 식별하는 능력, NIV2는 여러 과제의 언어 이해와 추론을 살피는 사례다. 서로 다른 Benchmark는 서로 다른 능력을 측정하므로 하나의 성능을 전체 품질로 확대하면 안 된다.

정형 정답이 없는 열린 평가에서는 응답 순위, 등급, 선호 비교 등을 사람이나 모델이 판단한다. 일반 LLM은 전문 영역의 지식이 부족할 수 있어, 인간 평가 자료로 평가용 모델을 조정하는 방법도 필요하다고 설명한다. 핵심 연결은 데이터 평가가 결국 평가자의 능력과 기준에도 의존한다는 점이다. [원문 §3.3.2](https://aclanthology.org/2024.findings-acl.658.pdf#page=8)

## 4. 향후 연구 방향

### 4.1. 복잡한 과제 분해

정해진 생성 순서를 사람이 설계하는 수준을 넘어, 모델이 필요한 추론과 도구 사용을 계획하게 할 것을 제안한다. 수학 문제와 해답을 만들 때 계산 도구로 중간 내용을 확인하는 경우가 그 예다. 기존 에이전트 연구를 참고해 데이터 생성 에이전트를 만들자는 제안이며, 이 논문이 그러한 시스템을 구현하고 검증한 것은 아니다. [원문 §4.1](https://aclanthology.org/2024.findings-acl.658.pdf#page=8)

### 4.2. 지식 강화

LLM이 잘 아는 영역과 잘 모르는 영역이 고르지 않으면, 조건을 자세히 적는 것만으로 전문 데이터의 문제를 해결하기 어렵다. 저자는 외부 지식 그래프나 검색 자료와 생성 과정을 연결하는 자동화된 제어를 제안한다. 외부 지식은 생성 조건을 정의하고 과제를 분해하는 데뿐 아니라 결과 평가에도 쓰일 수 있다. §3.1의 프롬프트 설계를 지식 기반의 지속적인 과정으로 확장하는 절이다. [원문 §4.2](https://aclanthology.org/2024.findings-acl.658.pdf#page=9)

### 4.3. 큰 언어 모델과 작은 언어 모델의 협력

§3.2의 보조 모델을 단순한 최종 검사자로 두지 않고, 학습 중 얻은 성능 피드백으로 다음 데이터 생성을 바꾸자는 방향이다. 기존 연구가 신뢰도 중심의 신호를 많이 사용하므로, 다른 출력 정보와 협업 구조를 탐색할 여지가 있다고 본다. 큰 모델의 생성 능력과 작은 과제 모델의 학습 반응을 연결하는 것이 핵심이며, 작은 모델이 항상 더 정확하다는 주장과는 다르다. [원문 §4.3](https://aclanthology.org/2024.findings-acl.658.pdf#page=9)

### 4.4. 사람과 모델의 협력

저자들은 편향과 유해한 데이터가 반복되면 모델이 사람의 의도에서 벗어날 수 있으므로, 필요한 인간 지식을 생성·검증 과정에 넣는 체계가 중요하다고 주장한다. 이 절은 그러한 개입을 지속 가능하게 만드는 조건도 다룬다. 결과를 읽고 이해하기 쉬워야 하며, 사전 지식 보강과 필터링으로 사람의 시간을 중요한 판단에 집중시키고, 반복 작업의 부담을 줄이는 상호작용을 설계해야 한다.

인간 개입이 필수라는 표현은 저자의 연구 방향에 관한 입장이다. 인간 개입이 전혀 없는 모든 생성 과정의 실패를 증명하는 정리나 비교 실험은 이 절에 없다. [원문 §4.4](https://aclanthology.org/2024.findings-acl.658.pdf#page=9)

## 5. 결론

이 논문의 기여는 Synthetic Data 연구를 생성·Curation·평가라는 연결된 과정으로 정리한 것이다. 모델의 생성 능력만 보는 대신, 그 능력을 특정 도메인 데이터셋 구축에 어떻게 활용하고 보정할지 판단하도록 한다. 결말에서 제시하는 모델들의 협력과 자기 개선은 전망이며, 앞 절의 방법 분류 및 한계 진단과 구별해 읽어야 한다. [원문 §5](https://aclanthology.org/2024.findings-acl.658.pdf#page=9)

## 한계

Synthetic Data는 영상과 음성 등에도 적용되지만, 이 논문은 지면 제한으로 텍스트 및 LLM 중심 방법을 주로 다룬다. 따라서 일반적인 작업 흐름을 제공한다고 해서 모든 데이터 형태를 동일한 깊이로 검토한 것은 아니다. 2024년의 분류 틀을 제공하는 자료로 읽어야 하며, 후속 연구 전체가 포함되었다고 해석할 수 없다. [원문 Limitations](https://aclanthology.org/2024.findings-acl.658.pdf#page=10)

## 윤리 진술

연구자와 산업 현장의 데이터 문제 해결에 도움이 될 수 있지만, Synthetic Data의 악용은 윤리 문제를 만들 수 있다고 밝힌다. 원문은 여기서 구체적인 위험 평가 절차나 법률 해석을 제시하지 않는다. 따라서 이 진술을 검증된 안전성 보장으로 확대하지 않는다. [원문 Ethics Statement](https://aclanthology.org/2024.findings-acl.658.pdf#page=10)

## 부록 A. 데이터 주석

Annotation은 입력을 고정한 생성 문제지만, 어떤 입력을 누구에게 맡길지가 별도의 문제다. <strong>Selective Annotation(선택적 주석)</strong>은 비싸고 정밀한 사람 작업과 상대적으로 저렴한 LLM 작업을 배분한다. 무작위 선택, 최대 엔트로피, 낮은 신뢰도, 군집 기반 선택 등이 비교 사례로 나온다.

여기서 <strong>Uncertainty(불확실성)</strong>는 현재 모델이 잘 판단하지 못하는 입력을 우선 선택하는 기준이다. 서베이는 인용 연구에서 이런 기준이 무작위보다 유리했던 결과를 소개한다. 또한 vote-k처럼 그래프를 이용해 다양하고 대표적인 샘플을 선택하는 방법도 다룬다. 모든 샘플을 더 강한 모델에 보내기보다, 비용이 큰 주석 작업의 대상을 잘 고르는 것이 이 부록의 논점이다. [원문 부록 A](https://aclanthology.org/2024.findings-acl.658.pdf#page=16)

## 부록 B. 튜닝 기법

생성 모델을 직접 미세조정하거나 <strong>Soft Prompting(학습 가능한 프롬프트)</strong>을 사용하는 연구를 본문의 프롬프트·작업 분해와 구별해 소개한다. 이런 접근은 생성 성능을 개선할 수 있지만 모델 내부에 접근할 수 있다는 전제가 흔하다. 내부를 바꿀 수 없는 모델에 적용하는 문제는 추가 탐색 과제로 남는다. 이 부록은 관련 분야의 기존 연구를 안내하며, 새 튜닝 알고리즘을 전개하지 않는다. [원문 부록 B](https://aclanthology.org/2024.findings-acl.658.pdf#page=16)

## 부록 C. 응용

**일반 과제**에는 텍스트 분류, 개체명 인식, 질의응답, 관계 추출, 자연어 추론이 포함된다. **전문 과제**에는 의료·임상·산업·표 데이터처럼 사람의 주석이 특히 어려운 영역이 포함된다. **다중양식 과제**에는 텍스트–이미지 검색, 시각 질의응답, 다중양식 지시 학습 등이 등장한다.

이 구분은 동일한 생성 흐름의 적용 범위를 보여준다. 각 분야가 본문에서 동일한 성능을 달성했다는 뜻은 아니며, 특히 전문 과제는 §4.2에서 논의한 외부 지식의 필요성과 연결된다. [원문 부록 C](https://aclanthology.org/2024.findings-acl.658.pdf#page=16)

## 부록 D. 벤치마크 데이터셋

Table 1은 생성 데이터로 학습한 모델을 평가할 대표 Benchmark를 과제·능력·도메인별로 정리한다. 분류와 질의응답, 수학 추론, 도구 사용 등 서로 다른 평가 대상이 섞여 있으므로 표를 단일 순위표로 읽으면 안 된다.

저자는 분류 연구에서 LLM 자체보다 생성 데이터로 학습한 작은 모델을 평가하는 경우가 흔하다고 덧붙인다. 또한 ToolBench처럼 LLM으로 생성된 평가 자료도 표시한다. 이는 평가에 쓰이는 데이터의 생성 방식과 평가받는 모델의 종류까지 확인해야 한다는, §3.3의 구분을 구체화한다. [원문 부록 D 및 Table 1](https://aclanthology.org/2024.findings-acl.658.pdf#page=17)
