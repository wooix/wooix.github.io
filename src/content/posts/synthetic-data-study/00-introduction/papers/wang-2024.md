## 초록

<strong>Large Language Model(대규모 언어 모델, LLM)</strong>의 발전에는 크고 다양한 고품질 데이터가 필요하지만, 학습 데이터 수요가 공급보다 빠르게 커진다는 문제에서 출발한다. 저자는 <strong>Data Augmentation(데이터 증강)</strong>과 <strong>Data Synthesis(데이터 합성)</strong>를 새로운 데이터 확보와 효율 개선의 두 축으로 본다.

이 서베이는 생성 모델의 종류만 분류하지 않는다. 데이터 준비부터 사전학습, 미세조정, 지시 학습, 선호 정렬, 응용까지 자료가 어디에 쓰이는지 살핀다. 이어 이해·논리·기억·생성 능력을 기준으로 같은 연구를 다시 읽는다. 두 관점을 연결하는 문헌 지도이며, 개별 방법을 동일한 조건에서 재실험한 성능 비교 논문은 아니다. [원문 초록](https://arxiv.org/html/2410.12896v1#abstract1)

## 1. 서론

고품질 데이터의 부족은 단순한 샘플 수 문제에 그치지 않는다. 수집 비용, 개인정보, 드문 언어와 새로운 지시의 부족이 함께 작용한다. 전통적인 이미지 변형과 규칙 기반 텍스트 생성은 이를 일부 완화하지만 실제 데이터의 복잡성을 충분히 재현하기 어렵다는 것이 저자의 진단이다.

여기서 중요한 범위 구분은 **LLM을 사용한 생성**과 **LLM을 개선하기 위한 생성**이다. 이 논문은 후자에 초점을 맞추므로, LLM이 아닌 시뮬레이터나 데이터 변형 방법도 포함한다. LLM이 만든 데이터로 작은 분류기만 학습시키는 연구에 머물지 않고, LLM 자체의 전체 개발 과정을 살펴보려는 목적이다.

방법의 분류와 사용 단계, 개선할 능력을 연결하면 동일한 연구가 여러 위치에 다시 나타날 수 있다. 이는 서로 독립된 기법의 개수를 세기 위한 분류라기보다, 연구를 다른 질문으로 재배치한 것이다. 서론의 데이터 고갈 전망도 당시의 증가 추세에 관한 문제 설정이며, 확정된 고갈 시점을 이 논문이 증명한 것은 아니다. [원문 §1](https://arxiv.org/html/2410.12896v1#S1)

## 2. 분류 체계

기존 샘플을 변형하거나 정보를 보태는 Data Augmentation과, 생성 모델 등을 이용해 새로운 샘플을 만드는 Data Synthesis를 구분한다. 두 방식 모두 데이터셋을 확장하지만 출발점과 조작 대상이 다르다. 다만 뒤의 실제 사례에는 두 성격이 함께 있는 방법도 있으므로, 이 구분을 서로 완전히 배타적인 규칙으로 볼 필요는 없다. [원문 §2](https://arxiv.org/html/2410.12896v1#S2)


<figure class="paper-figure" id="figure-4"><a href="https://arxiv.org/html/2410.12896v1/time.png" target="_blank" rel="noopener"><img width="476" height="293" src="https://arxiv.org/html/2410.12896v1/time.png" alt="2022–2024년 대표 방법의 등장 시기와 생성 방식 분류." loading="lazy" /></a><figcaption>Figure 4. 2022–2024년 대표 방법의 등장 시기와 생성 방식 분류. <a href="https://arxiv.org/html/2410.12896v1#S2.F4">원문</a></figcaption></figure>

가지의 시간 표기를 따라 대표 방법이 등장한 흐름을 읽고, 오른쪽 위 범례의 네 색으로 범용 모델 증류·도메인 모델 증류·자기 개선·증강을 구별한다. 선은 연대기 배치를 위한 것이며 특정 방법이 다른 방법보다 우월하거나 직접 계승했다는 관계를 모두 뜻하지 않는다. 원문 본문과 도표에서 일부 방법의 분류가 겹치거나 다르게 나타나므로 하나의 색을 배타적인 정의로 사용하지 않는다.

### 2.1. 데이터 증강

Data Augmentation은 기존 자료의 핵심 특징을 크게 바꾸지 않으면서 변형·섭동·추가 정보를 통해 종류와 양을 늘리는 접근이다. 이미지와 텍스트 각각의 변형뿐 아니라 이미지–텍스트 쌍의 대응을 유지하는 다중양식 변형도 다룬다. 이후 세 하위 범주는 무엇을 추가하거나 바꾸는지에 따라 나뉜다.

#### 2.1.1. 데이터 라벨링

<strong>Data Labeling(데이터 라벨링)</strong>은 기존의 라벨 없는 입력에 감독 신호를 붙인다. 정치적 메시지의 분류나 이미지에 대한 질문·답의 의사 라벨이 예다. 새로운 입력을 만드는 것보다, 이미 확보한 입력을 학습에 쓸 수 있게 만드는 역할이 중심이다.

#### 2.1.2. 데이터 재구성

<strong>Data Reformation(데이터 재구성)</strong>은 기존 자료의 표현이나 구조를 변형한다. 단어 치환 같은 전통적 접근과 LLM이 만드는 반사실적 변형이 함께 포함된다. 목표는 아무 문장이나 늘리는 것이 아니라 원래 과제와 관련된 변화의 범위를 넓히는 것이다.

#### 2.1.3. 공동 주석

<strong>Co-Annotation(공동 주석)</strong>은 사람과 LLM이 주석 작업을 나눠 수행한다. CoAnnotating은 LLM의 불확실성을 이용해 사람에게 보낼 자료를 정하는 사례다. 이 범주의 핵심은 완전 자동화가 아니라 비용과 판단 품질의 배분이다. [원문 §2.1](https://arxiv.org/html/2410.12896v1#S2.SS1)

### 2.2. 데이터 합성

Data Synthesis는 생성 모델 등을 통해 새로운 자료를 만드는 접근이다. 여기서는 생성 기술의 구조보다, 생성기와 학습 대상 모델의 관계를 기준으로 세 범주를 제시한다.

#### 2.2.1. 범용 모델 증류

<strong>General Model Distillation(범용 모델 증류)</strong>은 강한 범용 모델이 만든 자료를 다른 모델의 학습에 활용한다. 이야기, 교과서, 연습문제, 지시–응답 자료 등이 매개체다. 모델의 파라미터를 직접 옮기는 것이 아니라 출력 데이터가 지식 전달의 통로가 된다.

#### 2.2.2. 도메인 모델 증류

<strong>Domain Model Distillation(도메인 모델 증류)</strong>은 전문 분야에 맞는 모델과 자료를 사용한다. 코드나 수학처럼 일반적인 언어 품질만으로 충분하지 않은 영역이 동기다. 저자는 기업 내부 자료의 제한과 전문 지식의 필요성도 이 범주를 설명하는 이유로 든다.

#### 2.2.3. 모델 자기 개선

<strong>Model Self-Improvement(모델 자기 개선)</strong>은 모델이 생성한 자료를 자신의 후속 학습에 다시 사용한다. Self-Instruct가 대표 사례다. ‘자기 생성’이라는 말이 사람의 시드, 기존 문서, 정답, 외부 검증까지 모두 없다는 의미는 아니다. 실제 사례에서 어떤 외부 정보가 유지되는지는 §3에서 다시 확인해야 한다. [원문 §2.2](https://arxiv.org/html/2410.12896v1#S2.SS2)

## 3. LLM 전체 생애주기의 데이터 합성과 증강

§2의 분류를 자료 준비와 각 학습 단계에 적용한다. 같은 데이터셋도 준비 과정, 학습에 투입하는 방식, 최종 응용이라는 서로 다른 관점에서 다시 등장한다. 표의 빈칸을 뜻하는 대시는 인용 문헌에서 해당 내용이 보고되지 않았다는 표시이며, 그 요소가 없다는 증거가 아니다. [원문 §3](https://arxiv.org/html/2410.12896v1#S3)

### 3.1. 데이터 준비

학습에 앞서 자료를 확보하고 형식을 맞추며 품질을 조절하는 단계다. 여기서는 General Model Distillation과 Data Augmentation으로 나눈다.

|---|---|---|---|
| Self-Instruct | 175 human-written samples | 52k instructions | 12/2022 |

[원문 Table 1](https://arxiv.org/html/2410.12896v1#S3.T1)의 일부 행과 열만 발췌했으며 셀의 이름과 단위를 보존했다. 원자료에서 무엇이 만들어지는지 비교하는 표이며 날짜는 원문 표의 표기다. 값이 데이터셋 이름인 행과 샘플 수인 행을 동일한 양적 척도로 비교할 수 없다. 전체 생성 방법이나 모든 학습 설정을 재현하는 표는 아니다.

#### 3.1.1. 범용 모델 증류

##### 시드에서 합성

소수의 예시나 주제에서 생성 범위를 확장한다. TinyStories는 제한된 기본 단어에서 이야기를 만들고, Case2Code는 함수에 맞는 입력을 생성한 뒤 실행기로 출력을 구한다. Self-Instruct와 Evol-Instruct는 반복적으로 과제 풀을 확장한다. 따라서 시드는 생성의 출발점이자 범위를 정하는 조건이다.

##### 추론 단계 합성

정답뿐 아니라 중간 풀이를 자료에 포함한다. <strong>Chain-of-Thought(사고 연쇄, CoT)</strong>와 <strong>Program-of-Thought(프로그램 기반 사고, PoT)</strong>가 대표적이다. MMIQC의 문제 확장과 MathInstruct의 풀이 형식은 답변 결과만으로 전달하기 어려운 추론 정보를 추가하려는 접근으로 배치된다.

##### 제어 가능한 합성

OSS-Instruct는 오픈소스 코드 조각, Genie는 내용–예제 대응, DIALOGIC은 주석 대화와 필터를 사용해 생성 방향을 제한한다. 생성의 자유도를 늘리는 것과 달리, 원하는 내용·형식·과제와의 관련성을 유지하는 것이 목적이다.

##### 처음부터 합성

UltraChat은 주제와 하위 주제에서 질문을 확장하고, Magpie는 정렬된 모델의 대화 템플릿을 이용해 사용자 지시를 생성한다. 원문에서 ‘처음부터’는 명시적인 시드 데이터셋 의존을 줄인다는 뜻이다. 생성 모델이 사전학습으로 얻은 지식까지 없다는 뜻은 아니다.

##### 다중양식 데이터 합성

기존 이미지에 풍부한 설명을 붙이는 ShareGPT4V, 이미지와 대화를 함께 만드는 StableLlava, 시각적 개념과 코드를 통해 그림을 만드는 Multimodal Self-Instruct 등을 소개한다. ChartLlama와 AnyInstruct는 자료 생성 과정을 여러 단계로 나눈다. 두 양식의 자료가 각각 존재하는 것에 더해, 서로 같은 내용을 가리키도록 생성 순서를 설계하는 문제다. [원문 §3.1.1](https://arxiv.org/html/2410.12896v1#S3.SS1.SSS1)

#### 3.1.2. 데이터 증강

##### 데이터 라벨링

기존 텍스트나 이미지에 라벨을 붙이고, 필요하면 위치·영역 설명·음향 특징 등 부가 정보를 제공한다. FullAnno와 음성 감정 주석 사례는 입력 정보를 풍부하게 하면 라벨 판단의 근거도 달라진다는 점을 보여준다. 일부 과제에서 사람보다 좋은 결과가 보고되었다는 사실을 모든 주석 작업으로 일반화하지 않는다.

##### 데이터 재구성

TinyGSM은 기존 수학 문제를 변형하고, CORE와 DISCO는 반사실적 변화를 만든다. ALIA는 이미지의 설명을 요약한 뒤 이미지 편집을 유도한다. 기존 자료를 조건으로 한다는 공통점 아래, 텍스트 표현·문제 구성·시각적 특성을 각각 바꾼다.

##### 공동 주석

CoAnnotating은 불확실성을 통해 작업을 배분하고, Dialgen은 모델이 만든 대화 일부를 사람이 확인·수정한 뒤 다음 대화를 생성한다. 사람의 판단이 최종 검사에만 있는 것이 아니라 생성 중간 단계에도 들어갈 수 있다는 의미다.

##### LLM을 사용하지 않는 방법

AMPS의 수학 스크립트와 Mind’s Eye의 물리 엔진처럼 계산 절차로 문제와 답을 만들 수 있다. Proof-Pile-2의 필터링과 군집 기반 가지치기도 함께 다룬다. 원문은 여기서 자료의 양을 늘리는 방법뿐 아니라 유용한 자료를 남기는 처리까지 넓은 Data Augmentation 범위에 포함한다. [원문 §3.1.2](https://arxiv.org/html/2410.12896v1#S3.SS1.SSS2)


### 3.2. 사전학습

<strong>Pre-Training(사전학습)</strong>에서는 많은 양의 자료가 필요하므로 생성의 규모, 문체, 양식, 지식 범위를 함께 조절한다.


**Table 2 발췌 — 사전학습에서의 원자료와 생성 자료**

| 방법·모델 | 원문 Data Source | 원문 Synthetic Data | 원문 Date |
|---|---|---|---|
| VILA-2 | MMC4, Coyo, ShareGPT4v | Images with re-captioned texts | 07/2024 |
| WRAP | C4 | Re-phrased texts | 01/2024 |
| KMLM | CC100 | knowledge-intensive multilingual data | 11/2021 |

[원문 Table 2](https://arxiv.org/html/2410.12896v1#S3.T2)의 일부 행과 열만 발췌했으며 셀의 이름과 단위를 보존했다. 원자료에서 무엇이 만들어지는지 비교하는 표이며 날짜는 원문 표의 표기다. 값이 데이터셋 이름인 행과 샘플 수인 행을 동일한 양적 척도로 비교할 수 없다. 전체 생성 방법이나 모든 학습 설정을 재현하는 표는 아니다.

#### 3.2.1. 모델 자기 개선

VILA-2는 현재 모델이 이미지의 길고 자세한 설명을 만들고 다음 학습에 사용하는 사례다. 생성 결과가 다음 모델의 입력이 되는 순환 구조라는 점이 중요하다. 원문은 이 사례를 모든 모델에서 동일한 개선이 보장되는 일반 법칙으로 증명하지 않는다.

#### 3.2.2. 범용 모델 증류

Phi 계열은 교과서형 자료, TinyDialogues는 대화, SciLitLLM은 과학 문헌 정제, AnyGPT는 다중양식 자료의 사례로 배치된다. 같은 Pre-Training이라도 필요한 데이터의 구조가 다르다는 점이 핵심이다. 웹 자료와 생성 자료의 혼합, 오류 수정과 필터링도 생성 자체만큼 중요한 역할을 한다.

#### 3.2.3. 데이터 증강

##### 데이터 재구성

WRAP은 웹 문서를 여러 문체로 바꿔 실제 자료와 함께 학습한다. bioR는 생성된 인물 소개를 더 자연스러운 전기 문체로 바꾸는 사례다. 같은 정보라도 표현 방식이 학습 자료의 성질을 바꿀 수 있다는 관점이다.

##### LLM을 사용하지 않는 방법

수학 문헌과 코드를 정제하거나, 지식 그래프를 순차적 텍스트로 바꾸거나, 물리 모델로 자료를 생성하는 방식이 소개된다. 목표가 LLM의 학습 개선이므로 생성기가 반드시 LLM일 필요는 없다는 서론의 범위를 다시 확인한다. [원문 §3.2](https://arxiv.org/html/2410.12896v1#S3.SS2)


### 3.3. 미세조정

<strong>Fine-Tuning(미세조정)</strong>에서는 이미 학습된 모델에 특정 과제의 감독 신호를 제공한다. 이 절은 자기 생성, 강한 교사의 생성, 기존 자료의 변형을 비교한다.


**Table 3 발췌 — 미세조정에서의 원자료와 생성 자료**

| 방법·모델 | 원문 Data Source | 원문 Synthetic Data | 원문 Date |
|---|---|---|---|
| STaR | Arithmetic, etc. | A rationale dataset | 03/2022 |
| LLM2LLM | GSM8k, etc. | task-specific datasets | 03/2024 |
| MetaMath | GSM8k, MATH | MetaMathQA | 09/2023 |

[원문 Table 3](https://arxiv.org/html/2410.12896v1#S3.T3)의 일부 행과 열만 발췌했으며 셀의 이름과 단위를 보존했다. 원자료에서 무엇이 만들어지는지 비교하는 표이며 날짜는 원문 표의 표기다. 값이 데이터셋 이름인 행과 샘플 수인 행을 동일한 양적 척도로 비교할 수 없다. 전체 생성 방법이나 모든 학습 설정을 재현하는 표는 아니다.

#### 3.3.1. 모델 자기 개선

##### 한 번의 자기 개선

모델이 풀이·번역·지시 자료를 만든 뒤 이를 활용해 후속 학습을 수행하는 방법을 묶는다. 높은 일관성의 풀이 선택, 정확한 경로를 남기는 거절 샘플링, 목표 언어로의 번역 등이 소개된다. 이 범주의 구분 기준은 자료의 생성 횟수 자체보다 학습 갱신을 반복하는 구조인지에 있다.

##### 반복적 자기 개선

STaR, ReST, ReST-EM, DeepSeek-Prover, SPIN은 생성과 선별·학습을 반복한다. ReST-EM의 경우 이전 반복에서 갱신된 모델을 그대로 계속 학습하는 방식과 기본 모델을 다시 학습하는 방식을 구별한다. 반복 과정에서 어느 모델을 갱신하고 무엇으로 선별하는지가 결과를 이해하는 핵심이다.

원문 도입은 다중양식 자기 개선도 세 번째 범주로 예고하지만, 이 소절에는 이에 대응하는 별도 설명 단락이 없다. 따라서 내용을 추정해 추가하지 않는다. [원문 §3.3.1](https://arxiv.org/html/2410.12896v1#S3.SS3.SSS1)

#### 3.3.2. 범용 모델 증류

##### 시드로 합성

Unnatural Instructions는 소수 예제에서 지시를 늘리고, Baize는 자기 대화로 자료를 만든다. CLINGEN과 HuaTuo는 임상 주제나 지식 그래프로 생성 조건을 구체화한다. 예제를 단순히 복사하는 대신 전문 정보와 출력 형식을 생성기에 전달하는 역할이 강조된다.

##### 반복적으로 데이터 합성

WizardLM과 WizardCoder는 지시를 진화시키고, LLM2LLM은 학생 모델의 오류를 찾아 교사에게 관련 예제를 요청한다. 전자는 과제 난이도와 범위를, 후자는 학생의 현재 약점을 생성 방향에 반영한다.

##### 추론 단계 합성

작은 모델이 교사의 말투만 모방할 수 있다는 문제에서 출발해, Orca와 Orca 2의 상세 설명 및 여러 추론 전략을 소개한다. MAmmoTH는 CoT와 PoT를 함께 사용한다. 출력 형식과 설명의 구조도 학습 신호의 일부라는 해석이다.

##### 분류 체계에 따른 합성

LAB과 GLAN은 시드의 무작위 확장 대신 지식·과제 분류 체계를 사용한다. SciLitIns는 분야 키워드와 과제 설명을 조합한다. 생성하기 쉬운 주제에 집중되는 현상을 줄이고, 어떤 영역이 포함되는지 계획하려는 접근이다.

##### 다중양식 데이터 합성

LLaVA, ChartLlama, LLaVA-Med, ShareGPT4V, NExT-GPT를 통해 시각·의료·양식 전환 지시를 학습하는 사례를 연결한다. 같은 모델을 조정하더라도 전문 어휘 정렬과 실제 대화 지시 학습이 다른 단계로 배치될 수 있다. [원문 §3.3.2](https://arxiv.org/html/2410.12896v1#S3.SS3.SSS2)

#### 3.3.3. 데이터 증강

##### 데이터 라벨링

라벨 없는 자료에 답과 선호를 붙이거나, 이미지에서 질문–답 의사 라벨을 만든다. 저자는 생성 뒤 중복·저품질 제거를 포함하는 흐름도 함께 소개한다. 추가 감독 신호의 양과 신뢰성이 모두 문제다.

##### 데이터 재구성

Symbol Tuning은 자연어 라벨을 기호로 바꿔 문맥의 대응 관계를 학습하게 한다. MetaMath와 MathGenie는 문제·풀이를 변형하고 검증하며, 의료 대화 자료는 정제하고 표현을 보완한다. 각각 무엇을 유지하고 무엇을 바꿀지가 다른 증강 설계다. [원문 §3.3.3](https://arxiv.org/html/2410.12896v1#S3.SS3.SSS3)


### 3.4. 지시 미세조정

<strong>Instruction Tuning(지시 미세조정)</strong>은 사용자의 요청을 따르는 행동에 초점을 맞춘다. 앞의 Fine-Tuning과 개념상 겹치지만, 원문은 지시 생성 방식과 응답 형식에 초점을 맞춰 별도 절로 다룬다.


**Table 4 발췌 — 지시 학습의 입력 자료와 생성 결과**

| 원문 방법 | 원문 Data Source | 원문 Synthetic Data |
|---|---|---|
| Self-Instruct | 175 human-written samples | 52k instructions |
| Backtranslation | 13.2k instruction examples | 502k instruction-output pairs |
| SPIN | 50k prompts from Ultrachat200k | 100k synthetic dataset |

[원문 Table 4](https://arxiv.org/html/2410.12896v1#S3.T4)의 일부 행·열을 발췌했다. 같은 지시 학습이라도 새 지시 생성, 기존 응답에서의 역방향 생성, 이전 모델 응답 활용처럼 자료 구성의 역할이 다르다. 원문 표가 적은 자료 수만 비교해 효율이나 성능 순위를 만들 수 없으며, 프롬프트·응답·쌍의 단위도 구별해야 한다.

#### 3.4.1. 범용 모델 증류

##### 단일 양식

Alpaca는 교사가 만든 지시–응답을 학생에게 전달하고, Alpagasus는 그중 품질이 낮은 자료를 제거한다. WizardLM은 지시의 깊이와 폭을 늘리며, Orca 계열은 추론 설명을 제공한다. LongForm의 역방향 지시 생성과 Baize의 자기 대화도 포함된다. 이 절의 비교축은 단순한 샘플 수가 아니라 어떤 행동을 보여주는 자료인지다.

##### 다중양식

LLaVA는 이미지의 설명 등 정보를 지시 자료로 바꾸고 시각 인코더와 언어 모델을 연결한다. 후속 사례들은 도구 사용, 의료 이미지, 상호작용으로 범위를 넓힌다. 이미지와 관련된 텍스트가 있다고 해서 자동으로 지시 수행 자료가 되는 것은 아니며, 질문과 행동의 형식으로 구성하는 과정이 필요하다. [원문 §3.4.1](https://arxiv.org/html/2410.12896v1#S3.SS4.SSS1)

#### 3.4.2. 모델 자기 개선

##### 단일 양식

Self-Instruct는 자신의 지시와 답을 만들고, Instruction Backtranslation은 기존 문서를 답으로 보고 그에 맞는 지시를 역으로 생성한다. SPIN은 이전 모델의 응답과 목표 자료를 구별하며, ReST-EM은 생성한 후보를 피드백으로 선별한다. Constitutional AI는 원칙에 따른 비평과 수정을, Toolformer는 도구 호출 정보를 만드는 과정을 다룬다.

##### 다중양식

SelTDA는 이미지에 조건화한 질문–답의 의사 라벨을 만든다. 기존 소규모 시각 질의응답 자료만으로 부족한 감독 신호를 모델 스스로 확장하는 역할이다. [원문 §3.4.2](https://arxiv.org/html/2410.12896v1#S3.SS4.SSS2)

#### 3.4.3. 데이터 증강

##### 데이터 라벨링

텍스트 분류, 번역용 의사 병렬 자료, 과학 질문의 CoT를 다룬다. 서로 다른 과제라도 기존 입력에 새로운 감독 정보를 추가한다는 공통점이 있다.

##### 데이터 재구성

CORE의 반사실적 편집, ALIA의 이미지 편집, ChatAug의 바꿔 쓰기는 입력의 변형 범위를 넓힌다. 원하는 과제 형식과 의미 관계를 유지하는 것이 전제다.

##### 공동 주석

CoAnnotating의 불확실성 기반 분담과 사람이 이해할 수 있는 모델 설명, ToolCoder의 도구 사용 주석을 연결한다. 이 절은 인간과 모델의 협력 범위를 넓게 잡고 있으므로 각 사례에서 실제로 사람이 수행하는 부분을 개별적으로 확인해야 한다. [원문 §3.4.3](https://arxiv.org/html/2410.12896v1#S3.SS4.SSS3)


### 3.5. 선호 정렬

<strong>Preference Alignment(선호 정렬)</strong>은 여러 가능한 응답 가운데 어떤 응답을 더 바람직하게 볼지 학습시키는 단계다. 생성되는 자료가 정답 하나뿐 아니라 비교, 평가, 비평, 수정으로 확장된다.

#### 3.5.1. 범용 모델 증류

강한 모델이 응답을 평가하거나 고쳐 학생의 학습 자료로 제공한다. <strong>Reinforcement Learning from AI Feedback(AI 피드백 기반 강화학습, RLAIF)</strong>와 UltraFeedback이 대표적으로 등장한다. 여러 교사를 사용하거나 교사의 출력을 학생에게 적합한지 선별해 편향과 난이도를 조절하는 접근도 다룬다.

Open Assistant와 HelpSteer처럼 사람의 기여가 큰 자료도 이 절에 함께 등장한다. 따라서 여기의 모든 데이터가 전부 AI가 만든 라벨로만 구성되었다고 읽지 않는다. 비평을 생성하는 능력과 그 비평이 실제 수정을 돕는 능력도 별도 평가 대상이다. [원문 §3.5.1](https://arxiv.org/html/2410.12896v1#S3.SS5.SSS1)

#### 3.5.2. 도메인 모델 증류

##### 안전 중심 상황

적대적인 대화와 유해성 주석을 이용해 안전한 응답을 학습한다. BAD, RealToxicityPrompts, BeaverTails 등이 소개되며, 단순한 자연스러움과 유해하지 않다는 판단이 다른 기준임을 보여준다.

##### 요약

사람이 요약쌍을 비교한 자료로 보상 모델을 학습하고 응답을 조정한다. 이 사례에서 선호 신호는 사람이 제공한다. 생성된 응답이 포함된다는 사실과 선호 라벨까지 자동 생성되었다는 사실은 구별해야 한다.

##### 수학 문제 해결

PRM800K는 풀이 전체의 최종 결과만이 아니라 단계별 판단을 제공하는 사례다. 지도 신호의 단위를 세분화해 논리 일관성과 오류 위치를 학습시키려는 목적이다.

##### 검색 기반 질의응답

WebGPT는 검색 환경과 인간 평가를 결합한다. 답변만 생성하는 것에서 근거를 찾는 행동과 그 결과의 평가까지 자료의 범위를 확장한다.

##### 코드 생성과 논리 추론

WizardCoder와 WizardMath는 전문 과제에 맞는 지시의 다양성과 복잡성을 늘린다. 이 소절의 분류는 전문 분야에 맞춘 감독 신호를 넓게 다루며, 모든 예제가 동일한 선호 최적화 알고리즘을 사용한다는 뜻은 아니다. [원문 §3.5.2](https://arxiv.org/html/2410.12896v1#S3.SS5.SSS2)

#### 3.5.3. 모델 자기 개선

##### 자기 피드백 순환

Constitutional AI와 RLAIF에서 출발해 현재 모델의 출력에 맞춰 선호를 선택하는 방식, 모델이 스스로 보상을 부여하는 방식으로 이어진다. <strong>Direct Preference Optimization(직접 선호 최적화, DPO)</strong>를 사용하는 Self-Rewarding, 원칙에 따라 점수를 바꾸는 SALMON 등이 소개된다. 평가 기준이 고정되어 있는지 모델과 함께 바뀌는지가 중요한 차이다.

##### 외부 평가 모델

Alpagasus의 필터링, Instruction Backtranslation의 선별, SteerLM의 속성 평가를 다룬다. 자기 개선 범주 안에서도 외부 판단과 기존 인간 자료가 사용될 수 있다. 원문은 Self-Rewarding처럼 앞 단락과 겹치는 사례도 다시 포함하므로 두 하위 범주를 완전히 배타적으로 읽지 않는다. [원문 §3.5.3](https://arxiv.org/html/2410.12896v1#S3.SS5.SSS3)

#### 3.5.4. 데이터 증강

##### 데이터 라벨링

응답의 순위와 비교를 만들거나, UltraInteract처럼 잘못된 응답을 피드백으로 수정해 선호 트리를 구성한다. 입력–정답 쌍을 넘어 여러 선택지와 개선 경로를 감독 신호로 만드는 방식이다.

##### 데이터 재구성

Self-Instruct의 과제 풀, LaMini-LM의 추가 지식, Auto Evol-Instruct의 규칙 개선, Instruction Backtranslation의 역방향 생성이 소개된다. 지시의 내용과 난이도를 바꾸어 선호 학습이 만나는 상황을 확장한다.

##### 공동 주석

BeaverTails와 HelpSteer2는 생성된 응답과 사람의 판단을 결합한다. 생성 모델이 후보를 공급하더라도 품질·안전성의 판단을 전부 대체하는 것은 아니라는 점이 중요하다. [원문 §3.5.4](https://arxiv.org/html/2410.12896v1#S3.SS5.SSS4)

### 3.6. 응용

전문 응용에서는 일반 언어의 유창성보다 해당 분야의 지식과 검증이 중요해진다. 이 절은 같은 생성 전략이 분야마다 어떤 자료와 검증기를 필요로 하는지 비교한다.

#### 3.6.1. 수학

CoT와 PoT, 문제 변형, 풀이 검증이 중심이다. MetaMath와 반복 문제 합성은 문제의 폭을 넓히고, STaR와 DeepSeek-Prover는 생성한 풀이·증명을 확인해 후속 학습에 사용한다. 풀이의 다양성과 정답 여부를 함께 다루되, 최종 답 확인과 단계별 타당성 확인은 같지 않다.

#### 3.6.2. 과학

분야마다 다른 형식을 먼저 정리하고 전문 키워드와 과제 설명으로 지시를 생성한다. SciLitLLM, ChemLLM, SciGLM은 문헌·질문·추론을 연결하는 사례다. 수식과 화학 표현 같은 전문 표기, 설명의 논리, 품질 분류기가 모두 자료 구성에 영향을 준다.

#### 3.6.3. 코드

실행기를 통해 후보의 동작을 확인할 수 있다는 점이 강조된다. 프로그래밍 퍼즐과 해답, 최적화 문제, 진화한 지시, 코드 조각에서 만든 문제, 질문–테스트–해답 묶음이 등장한다. 실행 확인은 제공한 조건에서 얻는 신호이며, 이 절이 모든 프로그램의 완전한 정확성을 증명하는 체계를 제시한 것은 아니다.

#### 3.6.4. 의료

기존 진료 문서와 대화를 정리하고, 전문 지식으로 질문–답과 다중 턴 대화를 만든다. DISC-MedLLM, HuatuoGPT 계열, ChatCounselor, ClinGen이 예다. 민감한 기록의 직접 사용을 줄이려는 지식 그래프 기반 생성도 소개하지만, 생성되었다는 사실만으로 개인정보 보호가 보장된다고 할 수는 없다. §5.3이 이 위험을 다시 다룬다.

#### 3.6.5. 법률

법률 설명의 구조, 전문성, 명료성을 높이는 자료를 만든다. DISC-LawLLM과 LawyerLLaMA는 추론과 설명, LawGPT는 표현 정제, WisdomInterrogatory는 대화 모사를 다룬다. 특히 원문은 LawyerLLaMA에서 전문가 자료가 자동 생성 자료보다 좋은 결과를 보인 사례도 소개한다. 생성량 증가가 항상 전문가 자료를 대체한다는 결론은 아니다.

#### 3.6.6. 기타

금융과 교육도 언급하지만 상세한 방법 비교는 제공하지 않는다. 전문 지식 밀도와 품질 요구가 높은 분야라는 전망 수준으로 설명하며, 본문에 없는 시스템이나 수치를 추가하지 않는다. [원문 §3.6](https://arxiv.org/html/2410.12896v1#S3.SS6)

## 4. 기능

앞 절이 ‘언제 쓰는가’를 물었다면, 여기서는 ‘어떤 능력과 연결되는가’를 묻는다. 이해·논리·기억·생성은 관찰할 기능의 분류이지, 모델 내부에 네 개의 독립 모듈이 구현되어 있다는 주장은 아니다. [원문 §4](https://arxiv.org/html/2410.12896v1#S4)

### 4.1. 이해

#### 텍스트 이해

지시의 깊이와 폭을 늘리고, 모델 응답과 사람 응답의 차이를 구별하고, 문서를 바꿔 쓰는 사례를 연결한다. 지시 수행을 위한 자료 구성과 내용의 의미를 포착하는 학습이 함께 놓인다.

#### 의미 라벨링

문서에 지시나 의미 라벨을 붙이는 방법을 다룬다. 사람과 LLM의 비용·성능 절충도 여기 포함된다. 무엇을 생성할지보다 입력의 어떤 성질을 감독 정보로 드러낼지가 중심이다.

#### 다중양식 이해

LLaVA, ChartLlama, Genixer는 이미지의 의미를 질문과 설명으로 연결한다. 이미지의 기호적 설명, 도표의 유형, 시각 지시 자료의 범위가 이해 능력과 연결되는 방식이다. [원문 §4.1](https://arxiv.org/html/2410.12896v1#S4.SS1)

### 4.2. 논리

#### 코드

ReST-EM의 선별, ToolCoder의 도구 호출, OSS-Instruct와 Case2Code의 문제 구성, 실행기 검증을 연결한다. 생성한 문자열이 실제 기능과 맞는지 확인하는 과정이 중요하다.

#### 수학

MathInstruct의 여러 분야·난이도와 혼합 풀이 형식, MMIQC의 반복 문제 합성을 설명한다. 같은 문제의 말투만 바꾸는 것보다 추론 경로와 문제 유형을 넓히는 역할이 강조된다.

#### 추론

Orca 계열의 설명, Constitutional AI의 비평, T-SciQ의 문제 분해, STaR의 풀이 보강, Symbol Tuning의 문맥 대응 학습을 묶는다. 여러 방법이 다른 신호를 사용하므로 자연스러운 설명이 곧 타당한 추론이라는 결론은 나오지 않는다. [원문 §4.2](https://arxiv.org/html/2410.12896v1#S4.SS2)

### 4.3. 기억

#### 절차 기억

<strong>Procedural Memory(절차 기억)</strong>는 과제를 수행하는 과정과 행동 순서를 다룬다. 에이전트 코드 구성과 Quiet-STaR의 중간 사고 생성 등이 예로 나온다. 여기의 기억은 저장 장치의 구체적인 구조라기보다 어떤 정보를 활용하는지에 대한 기능적 분류다.

#### 의미 기억

<strong>Semantic Memory(의미 기억)</strong>는 지식 그래프, 문서, API처럼 기호로 표현할 수 있는 지식을 다룬다. AutoKG는 외부 자료와 협업을, KPC는 문서의 예외 처리 지식을, De-Hallucinator는 실제 API 참조를 생성에 연결한다.

#### 일화 기억

<strong>Episodic Memory(일화 기억)</strong>는 현재 상황과 관련된 경험·맥락 정보를 뜻한다. Persona Hub의 페르소나, AceCoder의 유사 프로그램, RepoCoder의 저장소 검색이 이 범주에 놓인다. 원문이 이런 사례를 실제 인간의 일화 기억과 동일한 내부 메커니즘으로 입증한 것은 아니다. [원문 §4.3](https://arxiv.org/html/2410.12896v1#S4.SS3)

### 4.4. 생성

#### 텍스트 생성

번역·바꿔 쓰기·이야기·대화·전문 응답을 만드는 방법을 연결한다. 외부 근거, 제어 조건, 반복 수정이 생성 내용의 성질을 바꾼다. 앞 절에서 소개한 방법들이 최종 출력의 일관성과 관련성이라는 관점으로 다시 정리된다.

#### 다중양식 생성

ALIA는 이미지 설명을 이용한 편집을 통해 시각적 변화를 만든다. 여기서는 양식 사이에 지시를 전달하는 역할이 강조되며, 다중양식 전체에 대한 새로운 성능 비교를 제공하지 않는다.

#### 검색 증강 생성

<strong>Retrieval-Augmented Generation(검색 증강 생성, RAG)</strong>은 외부 자료를 출력 생성에 연결한다. GraphRAG는 그래프 기반의 전체 문서 집합 요약, RankRAG는 관련성 판단과 응답 생성, LongRAG는 긴 검색·읽기 단위를 다룬다. 이 사례들은 데이터셋 합성만이 아니라 생성 시 외부 지식을 활용하는 방식까지 포함하므로, 서베이의 기능 분류가 학습 데이터 구축보다 넓다는 점을 보여준다. [원문 §4.4](https://arxiv.org/html/2410.12896v1#S4.SS4)

## 5. 과제와 한계

### 5.1. 합성과 증강 방법

#### LLM에 대한 의존

생성 데이터의 품질이 생성기의 지식과 추론 능력에 제한될 수 있다. 저자는 작은 모델로 만든 자료가 모든 능력을 충분히 개선하지 못할 가능성을 제기한다. 생성기가 강하면 모든 문제가 해결된다는 의미는 아니다.

#### 모델 학습의 평가와 오염 제거가 복잡해지는 문제

공개 평가 자료와 관련된 내용이 변형되어 학습에 들어오면 단순한 토큰 중복 검사로 찾기 어려워진다. 저자는 보호된 내부 평가 자료를 유지하는 방향을 권고한다. 이는 원문 일치 여부만으로 평가 독립성을 판단하기 어렵다는 문제다.

#### RLAIF의 불확실성과 탐색 복잡성

유용한 피드백을 얻기 위해 많은 후보와 질의를 탐색해야 하고, AI 평가가 인간 선호를 얼마나 잘 대표하는지도 남은 문제라고 본다. 원문의 강한 의문 표현은 저자의 한계 진단이며, 모든 AI 피드백이 무효라는 실험적 증명은 아니다.

#### 불안정하고 일관되지 않은 논리 경로

일부 단계나 최종 답만 검사하면 중간 오류를 놓칠 수 있다. 지식 기반과 형식적 도구의 결합을 제안하지만, 이 서베이 자체가 모든 추론 단계를 검증하는 방법을 제시하지는 않는다. [원문 §5.1](https://arxiv.org/html/2410.12896v1#S5.SS1)

### 5.2. 데이터 품질

#### 데이터 다양성

정해진 템플릿은 비슷한 표현을 반복할 수 있다. 실제 언어의 관용구·문화·맥락이 부족하면 자료량이 많아도 노출 범위는 좁을 수 있다.

#### 긴 꼬리 현상

흔한 언어와 과제가 주로 생성되고 드문 지시·전문 용어는 적게 포함될 수 있다. 생성량 증가와 희소 영역의 개선은 별개라는 논점이다.

#### 신뢰성

문장이 유창하고 선호에 맞더라도 사실이나 최신성이 틀릴 수 있다. 원래 자료와 생성기의 편향도 이어질 수 있으므로, 표면적인 품질을 내용의 신뢰성으로 대체할 수 없다.

#### 분포 불일치

생성 자료의 표현과 맥락이 실제 사용자 자료와 다를 수 있다. 원본의 편향뿐 아니라 대화 상황의 부족도 차이를 만든다. 따라서 정답성만 검사하는 것으로 실제 사용 환경의 적합성까지 확인되지는 않는다. [원문 §5.2](https://arxiv.org/html/2410.12896v1#S5.SS2)

### 5.3. 데이터 합성과 증강의 영향

#### 개인정보

실제 개인의 흔적이나 특징이 생성 자료에 남을 수 있다. 출처 추적을 위한 워터마킹도 개인정보와 효용의 균형을 고려해야 한다고 설명한다. 인공 생성과 익명성을 동일시하지 않는다.

#### 보안

생성 과정에 적대적 자료나 백도어가 들어갈 위험과, 원자료의 민감한 패턴이 복원될 가능성을 다룬다. 구체적 공격 절차를 제안하는 절이 아니라 데이터 생성 과정도 공격 표면이 된다는 지적이다.

#### 사회적 영향

소유권, 허위 정보, 실제 인물 모사, 편향의 재생산, 문화적 적합성을 논의한다. 서로 다른 사회의 맥락을 하나의 생성 기준으로 충분히 대표할 수 있는지도 문제로 남는다. 이 절은 법률적 결론보다 연구·운영상 고려할 영향을 정리한다. [원문 §5.3](https://arxiv.org/html/2410.12896v1#S5.SS3)

### 5.4. 서로 다른 응용과 과제에 미치는 영향

#### 일반화

생성된 패턴에 맞춰 학습한 모델이 새로운 실제 상황에서는 잘 작동하지 않을 수 있다. 의료 기관마다 절차와 인구 구성이 다르다는 예는 같은 전문 분야 안에서도 분포가 달라진다는 점을 보여준다.

#### 전이 가능성과 도메인 적응

한 영역에 맞춰 만든 자료를 다른 영역으로 옮기는 데에는 추가 문제가 있다. 예를 들어 격식 있는 대화로 만든 자료가 실제의 비격식 대화와 맞지 않을 수 있다. 자료가 올바른지와 다른 환경에서도 도움이 되는지는 별도 평가 대상이다. [원문 §5.4](https://arxiv.org/html/2410.12896v1#S5.SS4)

### 5.5. 미래 방향

#### 다중양식 합성

텍스트·이미지·음성·센서 정보를 결합해 더 풍부한 자료를 만들자는 방향이다. 자료 유형을 늘리는 것뿐 아니라 대응 관계를 유지하는 문제가 따라온다.

#### 실시간 합성

현재 사용자 입력에 따라 자료를 생성하고 상호작용을 조정하는 방향을 제안한다. 가상 비서와 게임 환경은 가능한 응용이며, 이 서베이가 구현해 검증한 결과는 아니다.

#### 도메인 모델 증류

범용 모델만 사용하는 대신 해당 영역에서 강한 전문 모델로 자료를 만들 것을 제안한다. 전문성이 실제 데이터 품질과 학습 효과로 이어지는지는 별도 확인이 필요한 연구 과제다.

#### 대규모 합성

Pre-Training에 필요한 규모까지 고품질 생성 자료를 확장하는 문제다. 많은 샘플을 생성할 수 있는 능력과 품질을 유지하며 확장하는 능력을 함께 요구한다.

#### 견고한 품질 평가 지표

언어 품질뿐 아니라 맥락 적합성, 다양성, 관련성, 편향을 평가하는 공통 기준을 제안한다. 현재의 단일 지표로 충분하다고 정리하지 않는다.

#### 윤리적 고려와 책임 있는 데이터 합성·증강

편향, 허위 정보, 오용을 다루기 위한 투명성·책임성과 운영 원칙이 필요하다고 주장한다. 앞 절의 위험을 실제 생성과 사용 과정에 반영해야 한다는 방향이며, 구체적인 인증 체계를 제시한 것은 아니다. [원문 §5.5](https://arxiv.org/html/2410.12896v1#S5.SS5)

## 6. 결론

이 논문의 핵심 기여는 Data Augmentation과 Data Synthesis를 LLM의 개발 단계 및 목표 능력에 연결한 분류 체계다. 방법 이름만 외우는 대신, 어떤 기존 자료를 사용하고 누가 무엇을 생성하며 그 자료가 어디에서 어떤 역할을 하는지 묻도록 한다.

분류에는 서로 겹치는 방법과 인간 주석·검색·비생성적 정제까지 포함된다. 따라서 모든 항목을 동일한 의미의 완전 자동 합성으로 간주하지 않고, 각 사례의 실제 감독 신호와 검증 절차를 구별해 읽는 것이 이 서베이를 활용하는 데 중요하다. [원문 §6](https://arxiv.org/html/2410.12896v1#S6)
